织法之杖：代码版本发布流程
更新日期：2026-11-14

一、每次发布必须遵循的顺序

1. 整理完整改动
以最近一次成功正式发布的 dist/releases/<版本>/content 和发布回执为基线，比较当前源码。
整理新增、调整、修复、默认配置变化、验证结果和未完成事项，先写入 docs/未发布改动.txt，交给用户审阅。
不要用开发工作区的旧 Git HEAD 代替上次正式版本基线；不要把已经发布的功能再次列为新增。

2. 用户人工确认对外内容
由用户决定哪些条目写入 Steam 更新记录、GitHub Release 和资料站。
确认前可以整理、检查、测试，但不得提升版本、准备正式快照、提交发布 commit 或上传。
如果用户已经在本轮明确给出更新说明并要求发布，就视为已确认，不重复询问。
对外说明保持简短，只说明新增、调整和修复；不把实现过程全部写进去。
确认后发现新的实质改动，或者对外说明增加了用户未选定的内容，先更新完整记录并重新确认相关内容。

3. 助手完成发布资料与版本准备
确定新版本号（通常 patch +1），准备两个 UTF-8 文件：
  docs/releases/X.Y.Z-public.txt：仅用户确认的中英文对外更新记录。
  docs/releases/X.Y.Z-commit.txt：第一行必须是 Release vX.Y.Z，空一行后记录全部改动和验证边界。
英文翻译与中文条目一一对应，不擅自添加宣传承诺。
更新 site/dist/updates.html，添加对应 data-release-version 的新记录，并更新 site/page_translations.en.json；英文页面由构建脚本生成。
更新 README 的当前版本、下载链接和本轮简介，保留历史版本记录。
执行 prepare：更新 mod/modinfo.lua 的版本和日期、导出源码、运行检查、打包并冻结文件。
检查冻结包和 Git 差异，再执行 commit：只在独立发布 checkout 中提交完整改动，暂不推送。
版本和文案必须进入同一个发布 commit；因此脚本顺序是 prepare → commit → publish。

4. 执行代码发布脚本
publish 必须使用已经准备且提交过的同一版本；不允许跳过前两步临时打包发布。
它依次执行：Git main 与版本标签原子推送 → GitHub 草稿及附件 → Steam Mod 内容更新 → 公开资料站部署 → GitHub 正式 Release。
完成后核对 Steam 回执、GitHub Release 非草稿状态、资料站中英文版本和更新记录。
随后将本轮已发布的内部清单归档，以新冻结包重新核对并更新 docs/当前状态.md 与 docs/未发布改动.txt；保留发布后新增的工作区差异，不直接清空未发布清单。版本、成功状态和差异可用 tools/context.py --release-diff 只读核对。
若用户要求安装，使用 tools/install_mod.py；安装器禁止游戏运行时覆盖本地文件。

二、脚本入口与命令

入口为项目根目录 release.ps1；跨平台等价入口为 python tools/release.py。
默认只显示计划，不改文件、不提交、不上传。默认 Steam 后端为 native，使用本机已登录的 Steam 客户端。
以下 X.Y.Z 是版本占位符，运行前替换为本次已确认的版本；新发布不得照抄历史已发布版本号，恢复时使用对应冻结版本。

只看计划：
  .\release.ps1 --version X.Y.Z --audience public

仅在用户确认对外内容后准备：
  .\release.ps1 --mode prepare --version X.Y.Z --audience public --notes-file docs/releases/X.Y.Z-public.txt --commit-file docs/releases/X.Y.Z-commit.txt --notes-approved

检查差异并提交（只写本地发布仓库）：
  git -C dist/github-public diff --stat
  .\release.ps1 --mode commit --resume X.Y.Z --audience public

发布已提交的冻结版本：
  .\release.ps1 --mode publish --resume X.Y.Z --audience public

--notes-approved 是助手对“本次说明已经用户人工确认”的明确记录，不是允许助手代替用户确认。
脚本会冻结对外说明的 SHA256 和完整 commit 正文。恢复时不能另传说明文件覆盖它们。
commit 从冻结的 commit.txt 读取完整正文，不再仅生成一句 Release vX.Y.Z。

三、代码发布的范围

Steam 只更新现有条目 3834454416 的 Mod 文件、经确认的更新记录和版本标签。
不调用 SetItemPreview、SetItemTitle、SetItemDescription 或 SetItemVisibility。
SteamCMD 的 VDF 同样不包含 previewfile、title、description 或 visibility。
发布包不再要求工坊封面文件、描述文件或 workshop-localizations.json；配置中保留这些路径供独立工具使用。
原生上传前后只读核验中英文标题、描述、封面、归属与可见性保持不变。
该方式也避免给旧 Klei 上传器创建的条目重复提交封面时发生上传失败。
游戏内资源、modicon 和 modinfo.lua 的本地模组描述仍属于 Mod 文件；这里排除的是工坊页面封面与介绍更新。

四、工坊封面与描述独立处理

仅在用户明确要求相关修改时，另行准备、检查并执行：
  描述和标题只读检查：.venv\Scripts\python.exe tools/steam_workshop_metadata.py --mode check
  发布中英文描述和标题：.venv\Scripts\python.exe tools/steam_workshop_metadata.py --mode publish
  发布主封面：.venv\Scripts\python.exe tools/steam_workshop_preview.py

这些工具不由 release.ps1 自动调用。旧的 --mode workshop 入口已移除，改用上述独立工具。
美术修改先读取 docs/art/00_美术任务流程.md 并遵循其中的规范。封面工具沿用旧 Klei 上传器的兼容路径，并核对公开图片与文件字节一致。
不要为了代码发布失败而顺手更新封面、描述或改变可见性。

五、环境与认证

Python 3.12+，依赖见 tools/requirements-dev.txt；项目入口优先使用 .venv。
需要 Git 和 GitHub CLI，以及能够访问目标仓库、Release、Actions 和 Pages 的授权。
GitHub 优先使用 GH_TOKEN/GITHUB_TOKEN 或 gh auth login；未配置 gh 时，可使用 Git Credential Manager 中 github.com 的已有凭据。
凭据仅进入当前发布进程及子进程环境，不打印、不写入日志、文件或 Git；不要求用户在聊天中提供 token。
Steam native 需要 Windows、64位Python、已登录的条目作者账号以及 DST 的 steam_api64.dll。
可用 --steam-api-dll 指定 DLL；默认自动寻找本机 DST 安装。
可选 SteamCMD：--steam-backend steamcmd --steamcmd "D:\Tools\SteamCMD\steamcmd.exe" --steam-user YOUR_LOGIN。
SteamCMD 登录密码/验证码只在其交互终端输入，不写入参数或配置。

发布目标见 tools/release_config.json。默认受众仍为 private；当前正式发布使用 --audience public。
脚本不改变仓库或工坊可见性。公开仓库和 GitHub Pages（Source: GitHub Actions）须已配置好。
私有发布仅上传资料站 ZIP 附件，不部署公开 Pages。

六、校验、失败与恢复

所有正式发布使用 dist/github-public 独立 checkout，开发工作区历史与暂存区不自动提交。
导出源文件包括 AGENTS.md；不导出游戏存档、凭据、临时日志和研究文件。
检查范围包括 Lua 语法与规则、资源、本地化、网站链接、发布流程回归测试。
快照在 dist/releases/X.Y.Z，包含 Mod、资料站ZIP、notes.txt、commit.txt、VDF、哈希与 state.json。
脚本检查快照、发布源码和当前commit是否一致，拒绝混合版本、额外文件、标签冲突及强制推送。

查看进度：
  .\release.ps1 --resume X.Y.Z
恢复发布：
  .\release.ps1 --mode publish --resume X.Y.Z --audience public
恢复本地提交：
  .\release.ps1 --mode commit --resume X.Y.Z --audience public

--resume 沿用原始确认和冻结文件，不读取后来改动的源码；已完成的阶段不会重复执行。
若 Pages 失败，GitHub Release 保持草稿，Steam 已完成的更新保留；修复或重试时仍使用同一版本。
原生 Steam 必须返回成功并完成回读核验；SteamCMD 必须在本次日志中确认指定条目 OK。不能手工伪造完成状态。
脚本通过 dist/.release.lock 防止并行发布。仅确认锁内进程已经结束后才可删除遗留锁。
准备阶段失败且尚无 state.json 时，保留现场；先检查版本和独立checkout改动，再修复，不自动reset/clean或改用新版本掩盖失败。
旧版全量发布快照缺少 release_kind=code 和说明确认记录，新脚本拒绝继续上传；可以用 plan 查看历史。确需恢复旧的未完成发布，先明确审核旧流程和剩余动作。
脚本测试必须使用临时仓库、假 Steam/GitHub 接口，不为验证流程实际发布一个新版本。
