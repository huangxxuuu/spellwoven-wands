暗雾生物控场设计方案
日期：2026-11-11
状态：用户已授权实施，核心代码已按本方案改造；未发布。本文保留设计依据，实际参数、适配范围与验收记录见《暗雾修饰实现与测试.md》和《暗雾Boss适配表.txt》。

一、本次用户确定的方向

暗卡作为法术修饰，子弹沿途留下黑雾，每团持续3–5秒并有随机性。
黑雾当前不对玩家产生效果，不修改实际照度，不沿用此前查理/原版黑暗机制方案。
小型生物：入雾后原地恐惧1秒，随后目盲、慌乱随机移动，直到离雾。
普通体型：立即丢失目标并慌乱；3单位内发现原本合法的攻击目标时可攻击；目标再次离开3单位时，沿最后感知方向继续移动一段，未重新发现且仍在雾中则回到慌乱。
大型生物/Boss：有可用吼叫动作则吼一次，再选择该生物范围较大的近距离原生招式驱雾，不固定攻击两次。已指定：独眼巨鹿普通攻击、熊獾拍地、龙蝇砸地。
驱雾招式保留原版伤害和附带效果，范围内相关目标按原规则结算。黑雾在招式实际命中时开始消散动画，不等整段攻击动画结束。
用户补充确认：受击驱散目前只限Boss驱雾招式，玩家、普通生物和其他攻击不默认驱散黑雾。
暗影类型：免疫负面效果，在雾中获得移速增益。

二、核心结论

普通效果可以集中实现，不需要逐prefab复制AI。
建议结构为：弹道留雾与区域管理 + 每生物临时状态组件 + 战斗候选过滤；另有分类与特殊动作适配表。
精确的Boss吼叫、近距离大范围招式及驱雾命中时点需要按状态机家族核验和适配。若要求覆盖所有原版/第三方Boss，适配表会随覆盖范围扩大，不能声称一个统一事件即可完成。
分类配置一行和完整重写一个生物AI是不同的工作量；可共享同一Brain/SG的生物共享策略。

三、弹道与区域

当前 definitions.lua:83 已把dark定义为modifier；需要改的是其效果参数和执行逻辑。旧dark_fog.lua依赖玩家/grue，必须移除这部分控制，不与新方案同时启用。
沿子弹实际走过并经碰撞裁剪的有效路径落雾；利用projectiles.lua的轨迹段，但不能在最终碰撞位置确定前就把雾铺到障碍物后面。
按距离采样而非每帧生成，快速弹体补齐中间点；反弹按真实分段，传送不连成长条。初始间距可试0.75–1单位，属于待测建议。
每团生成时由服务端一次性抽取3–5秒寿命；客户端只负责表现，不各自抽取。
优先沿用半径2作为初始实验值；用户本轮没有重新指定半径，仍需平衡。
所有覆盖统一判断：生物离开最后一团黑雾才恢复。穿过重叠雾时不重复触发恐惧、不重置近距追踪、不叠加移速。
区域采用共享更新和空间候选缓存；只处理附近活跃实体，并保留单施法者/世界预算。沿途留雾不能机械照搬旧16团额度与每团7个动画子实体，否则密集弹幕会快速淘汰旧雾或放大视觉开销，应重新定量验收。
非弹道、永久驻场法术的产雾规则另行定义，不默认变成每帧无限产雾。

四、分类优先级

玩家/玩家幽灵先排除 → 暗影类型 → 大型/Boss → 小型 → 普通；不能移动或特殊生命周期的生物走专门策略。
smallcreature、largecreature、epic可作为初筛，但标签不是完整体型系统。
原版证据：spider.lua:587–592和rabbit.lua:347–355有smallcreature；hound和普通pigman没有一致的体型标签；beefalo.lua:1090–1095有largecreature；deerclops/bearger/dragonfly有epic与largecreature。
shadowcreature.lua:276–286同时使用shadowcreature、shadow、shadow_aligned。暗影阵营、暗影形态、暗影视觉表现不能不加区分地全部等同于本卡的“暗影类型”。先列明确家族，保留第三方注册接口。
不建议按美术高度/GetVisualBB或血量划分控制档位：换皮、缩放、动作与生命强化不应自动改变控场规则。

五、统一控制流程

首选每个受影响生物一个服务端临时组件，保存覆盖来源、阶段、阶段截止时间、最后感知方向和本轮驱雾状态。
对支持的普通地面生物，用StopBrain("nw_fog_control")暂时停止原脑，保留原状态机；组件发出移动/攻击意图，离雾用相同reason恢复。
不是SetBrain永久换脑，也不每帧强制GoToState("idle")。
entityscript.lua:1104–1125按原因集合停脑/恢复，因此不会清除sleep/frozen等其他停脑原因。
但brain.lua:206–224、246–258显示停止会调OnStop/BT.Stop，重启会调OnStart并重新初始化，可能重置局部AI计时。首批生物必须验证出雾后的觅食、跟随、回家、战斗恢复；不适合这种暂停的家族可改用共享Brain高优先级节点。
原版只有AddBrainPostInit(brain,fn)，没有AddBrainPostInitAny（modutil.lua:627–633）。按Brain家族注册共享节点仍不等于逐prefab写AI；但Brain:OnUpdate会在BT前执行DoUpdate，单纯插入BT节点不一定屏蔽额外逻辑。

小型：首次覆盖 → fear_hold(1秒，不主动移动/攻击) → blind_wander → 离雾恢复。
恐惧逻辑统一；有合适惊恐表现的家族使用它，没有的先用自然停顿表现，不强行播放不存在的动画。若要求每种生物都有专属恐惧动作，则这部分也需家族适配。
1秒只在一次连续入雾时触发，重叠不重触发；建议增加短暂再触发冷却，防止边缘进出造成永久定身，具体数值待定。

普通：入雾清旧目标 → panic → 发现3单位内合法目标 → near_combat。
目标超出3单位：清除目标引用，用仍在感知范围内时记录的位置/方向进行blind_continue；建议初始试0.6–1秒，然后回panic。
blind_continue不得继续读取远处目标的实时坐标，否则只是伪装成盲走的追踪。
任意阶段离开黑雾立即撤销雾控制，让原脑自行重新决策；不直接恢复入雾前的旧目标。
3单位是感知和允许新攻击的上限，不把原攻击距离统一改成3，不跳过冷却，不把所有生物变成长手怪。

目标必须来自原有仇恨规则：原retarget、受击反击、共享仇恨或明确的家族近距候选策略。
不能在周围3单位内挑任意CanTarget对象；CanTarget不代表该物种原本就应该仇恨它。中立动物、随从和同阵营不能因此互殴。
玩家不受雾本身负面效果，但仍可以是怪物原本合法的近距攻击目标。
只清combat.target不够：受击反击、共享目标和重索敌会再次写入。按受影响实例过滤SetTarget/必要的候选入口，并在统一更新中及时检查现目标是否超出3单位；原keeptargetfn检查周期可能约1秒。
某些原targetfn先挑远处优先目标再返回，直接拒绝可能漏掉近处次优目标；要求完整近距感知时，按AI家族补近距候选函数。

六、大型/Boss驱雾

通用组件调度“吼叫可选 → 一次选定的近距离大范围原生招式 → 自然收招”；招式内部可以有多次伤害脉冲，不人为统一成挥击次数。
当前选择：独眼巨鹿执行普通攻击；熊獾执行拍地；龙蝇执行砸地。其他Boss按同样原则选择合适近距离招式，不一律套普通攻击，也不为了驱雾自动选全屏技能。
适配器须明确：可安全启动的状态、吼叫入口、无指定目标时如何原地出招、攻击有效范围及其生效事件、完成/中断标记、关联伤害FX的来源。
原招式的伤害、击退、冻结、破坏等实际附带效果沿原代码执行；对哪些目标生效继续按该招式原有规则。驱雾不另调一次DoAttack，不额外制造伤害，不把有伤招式改为无伤表演。
原版差异：SGdeerclops.lua:856起的attack会在timeline生成冰刺；熊獾拍地和龙蝇砸地走groundpounder组件。巨鹿不能仅在生成冰刺时把一整片范围立即清空，应追随对应冰刺/范围伤害真正生效的区域与时点。
当前源码核查：SGbearger.lua:1165–1169在第20帧调用GroundPound；SGdragonfly.lua:620–633的一次pound在第2、9、20帧分别调用GroundPound。两者使用RingMode，groundpounder.lua:331–357安排延迟环，真正伤害/破坏处理在DestroyRing:170–235，驱雾通知应跟随该环实际生效而非仅在GroundPound被调用时触发。
巨鹿SGdeerclops.lua:890–891第31帧安排冰刺，DoSpawnIceSpike:84–87通过hitdelay延迟执行DoIceSpikeAOE:41–62。需要针对该局部AOE路径做窄适配，不能用onhitother代替：只有雾、没有可被伤害生物时也必须能驱散。
DoIceSpikeAOE是SG内部局部函数，并无公开组件回调；准确复用需确认闭包链并做受版本检查保护的适配，不能假设AddStategraphPostInit可以直接访问。巨鹿这部分有单独的原版更新维护成本。
不通过制造假目标去欺骗原版战斗，不把黑雾加入combat目标集合，也不只PlayAnimation来代替原生出招。无人处于攻击范围时仍能完成驱雾动作；存在相关目标时自然结算原伤害和效果。
驱雾统一走区域命中接口：实际攻击生效 → 找到与该次有效攻击区域相交的活动雾团 → 开始消散。只命中覆盖到的雾团，不沿连通雾带清空整片地图。
GroundPound等公共伤害入口可以共享追加通知，但必须检查受支持Boss及本次驱雾施招标记；普通攻击、其他地震/爆炸不能因此自动驱雾。需区分一次招式的多次脉冲，同一团雾只开始消散一次。
施招标记必须随每次延迟环/冰刺上下文传递，不能到命中时只检查Boss是否仍处于原SG状态；原生每次pulse的伤害去重仍各自独立，不因统一驱雾而合并。
普通生物的3单位感知/新攻击过滤不套用到Boss驱雾AOE，避免截断原招实际范围。
区域形状与时点跟随原招式：圆形冲击、扇形挥击、延伸冰刺等不能全部换成统一固定圆。衍生FX应携带对应施招来源，避免清雾作用误归属或与其他攻击混淆。
每次连续覆盖只触发一轮，并建议增加驱雾冷却，避免新弹道雾让Boss无限吼叫/出招。
冻结、睡眠、死亡、转阶段等优先；若雾已自然消失，取消尚未开始的驱雾动作。已经开始的原生招式正常收尾，即使第一段已清掉周围雾，也不能把后续合法伤害脉冲提前截断。
未适配的特殊Boss先保守跳过复杂动作并明确覆盖范围，不强制进入猜测状态；要满足完整动作要求则补适配再宣称支持。

雾团采用active → dissipating → removed三个生命周期阶段。
用户已确认命中时开始消散动画。配套建议：开始消散时立即撤销该团的有效区域，客户端完成短消散动画后才删除实体；避免画面已散而控制仍在，也避免直接删除没有过渡。
如果生物还被其他活动雾团覆盖，继续保留效果；已开始消散的雾不再提供覆盖。移速增益与负面状态都按同一有效覆盖规则撤销。
具体消散动画时长尚未指定。客户端表现通过服务端同步的消散状态启动，重复命中或寿命到期不得重播、叠加或延长消散。

七、暗影生物

不进入恐惧/目盲/慌乱，不停原脑、不清目标，只加独立移速乘区。
使用locomotor:SetExternalSpeedMultiplier(source,key,multiplier)，离开所有雾后RemoveExternalSpeedMultiplier。原版locomotor.lua:490–523提供该机制。
初始可试1.25倍移速，数值为建议；重叠雾不叠加，不改原walkspeed/runspeed以免覆盖其他状态。没有locomotor或速度来自特殊状态机的暗影类型需要另查实际覆盖。

八、状态边界与验收

统一组件不应在死亡、冻睡、石化、击退、沉没、转阶段等状态持续发移动攻击指令。停脑不等于停状态机。
清移动路径与清BufferedAction是两回事；locomotor:Stop没有清buffered action（locomotor.lua:1091–1113），而ClearBufferedAction会执行失败回调（entityscript.lua:1588–1592），不能在特殊事务状态无差别清除。
“立即丢失目标”不自动取消已提交攻击。SGhound.lua:225–237会把目标缓存进sg.statemem.target后延时攻击；默认建议阻止后续远距索敌/新出手，已经发出的弹体不消失。若要求当前前摇也立即中止，需另做可安全打断状态适配。
随机移动要遵守原水陆、地面、碰撞和寻路能力；参考Wander选点，不随机Teleport，不让地面生物盲走入海。
离雾、雾被驱散、实体死亡/移除/休眠、世界切换均需解除本效果自己添加的控制和速度项，避免唤醒后永久慌乱。

首批验证：兔子、蜘蛛、猎犬、猪人/随从、皮弗娄牛、爬行恐惧/尖嘴恐惧、独眼巨鹿、熊獾。
重点场景：重叠与边缘进出；远处受击重新仇恨；友军共享目标；中立与随从敌我；3单位边界后目标突然转向；攻击前摇时入雾；冻睡期间进退雾；雾在Boss动作中消失；驱雾招式中断；单招多次脉冲与冰刺延迟命中；范围内有/无伤害目标；雾消散与效果撤销同步；其他攻击不误驱散；实体休眠/唤醒；高速反弹弹道与密集弹幕。
所有判定由所在世界服务器负责，客户端展示雾与原生同步动作。初始参数采用间距1、半径2、盲走0.8秒、暗影1.25倍速度、驱雾8秒冷却、0.4秒淡出；这些是可继续调节的实施值。实际测试结果见实现记录，不能以本设计讨论代替实机验收。
