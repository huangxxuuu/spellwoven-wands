1. 制作实体法术收集册／收集图鉴。
2. 三个主页面：收集进度、分类查看、按标签查看。
3. 未收集卡显示问号；已收集卡显示更大、更清晰的牌面。
4. 分类和标签使用第 20 号文档中的最新体系。
5. 收集册需要物品栏图标、掉落地面的外观、打开后的界面。
6. 每张卡可点击单独查看，展示卡牌悬空和旋转效果；卡面必须足够精美，卡背必须有值得欣赏的纹理。
7. 本阶段先设计方案。

沿用此前文案要求：作用描述简短，但伤害、法力消耗、施放间隔、充能等基础属性必须保留。加速度、阻尼、扫描周期等细节不挤进默认说明，在资料站详细数据中查看。

## 3. 实体收集册提案

建议名「织法收集册」。采用饥荒式手绘旧书：皮革封面、纸页、墨线、克制的包角。书本材质与最终卡框风格协调，不提前锁定古籍铜角候选。

- 物品栏：略微打开的厚书，封面是两把交叉法杖，三枚书签从页间露出；小尺寸先保证书本与纹章轮廓。
- 地面：合拢、有书脊和厚度、露出少量卡片；落地轻弹，闲置时静止。脚点和阴影贴地。
- 入口：物品栏右键「翻阅」，无需装备或靠近建筑。
- 建议配方：科学机器解锁，莎草纸 ×2、树枝 ×2、奥术粉尘 ×1；无耐久，可重复制作。此配方尚待确认。
- 建议书本只作为入口，收藏记录归玩家，书的丢失、销毁、借出不改变收藏。

## 4. 三个主页面

顶部固定「收集进度／分类查看／标签查看」三个书签。每页保留自己的翻页、排序、筛选状态。共用同一套卡牌数据、网格与详情，避免重复维护。

### 4.1 收集进度

- 顶部显示总进度和三个主类分进度。
- 建议默认 6 列 ×2 行，一页 12 张；较小界面改 4 列，优先保证卡面可读。
- 已收集显示彩色完整卡面与名称；未收集显示统一封存样式和问号，不透露主图或名称。
- 新收集卡角落显示小书签，打开详情后清除。
- 提供「全部／已收集／未收集」、默认顺序／最近收集排序。
- 默认顺序中卡槽位置稳定，不因解锁自动重排。
- 未收集卡也能点击：显示封存卡及「尚未收集」。建议仅给制作或掉落等宽泛线索，具体配方与身份保持隐藏；是否给线索尚待确认。

### 4.2 分类查看

左侧三个主类及各自已收集／总数，右侧大卡面网格。主类只允许一个，外轮廓与物品栏和地面版保持一致。

| 主类 | 外轮廓 | 职责 |
| --- | --- | --- |
| 基础法术 | 轻切角矩形 | 产生投射物、近战、瞬发效果、实体、范围场、音乐或载荷载体 |
| 法术修饰 | 上下尖的竖向六边形 | 改变伤害、弹道、速度、寿命、目标、费用、充能等 |
| 施法控制 | 顶部中央宽凹口矩形 | 多重抽取、输出复制、方向组织、为下一载体附加载荷释放机制 |

分类看实际行为，不直接由运行时 `kind` 推导。例：碰撞火花仍是基础法术；独立碰撞触发修饰是施法控制；命中爆炸是法术修饰；复制输出属于施法控制；费用和充能修正属于法术修饰。

### 4.3 标签查看

左侧按四个维度组织标签，右侧显示匹配结果。以下词表来自第 20 号文档的起点示例，不是已完成的逐卡映射。

| 维度 | 标签示例 |
| --- | --- |
| 作用形态 | 投射物、近战、瞬发、地面实体、范围场 |
| 修正方向 | 弹道、速度、伤害、寿命、目标、费用、充能 |
| 释放机制 | 碰撞载荷、定时载荷、被击破载荷、多重抽取、输出复制 |
| 实用用途 | 治疗、防御、采集、音乐、照明 |

- 支持跨主类筛选，可附加主类条件。
- 多选提供明确的「满足全部标签／满足任一标签」切换，避免含糊的组合语义。
- 显示已选条件、匹配数量，支持逐项取消和清空；无结果时保留条件并提示放宽。
- 标签描述卡本身的稳定属性，不记录本次组合临时赋予的属性，不把数值做成标签。
- 未收集卡筛选后仍是问号；允许透露其属于所选范围，不通过名称搜索、悬停或关联卡泄露隐藏名称和规则。

## 5. 单卡鉴赏与详情

点击卡面后，从书页原位浮起并放大，书页背景稍暗。左侧展示卡牌，右侧信息，底部观赏操作。

### 5.1 动画和操作

- 默认正面略倾斜、轻微上下浮动，下方柔和阴影。
- 左右拖动绕竖轴转动，看到正面、纸边、背面；不是把正面镜像成背面。
- 提供「翻到背面／自动旋转／回正」；自动旋转默认关闭。
- 停止观赏、进入阅读状态时默认正面；操作信息区不带动卡牌晃动。
- 「纯观赏」隐藏信息，让卡牌居中放大。
- 文字保持平直可读，不贴到旋转平面。
- 纸边是薄纸，不能做成厚金属板；透明凹口、尖顶在侧面和背面也必须成立。
- 先做旋转样板验证 DST UI 能力，尚未选定真实几何、分层动画或预制转面等实现方式，不能承诺仅缩放图片就能达到目标。

### 5.2 信息顺序

卡名 → 主类与完整标签 → 一句话作用 → 作用范围／依赖 → 基础属性 → 获取方式与关联变体。

- 范围按真实实现写明「本施法组」「下一载体」「后续法术作为载荷」「本轮法杖充能」等，不笼统写成下一张卡。
- 显示适用的伤害、法力、施放间隔变化、充能变化等基础属性，不适用的字段不占空行。
- 获取方式含建筑、配方、掉落来源；规则例外可折叠展示。
- 提供对应资料站卡牌页面入口，通过默认浏览器打开。
- 普通、碰撞、定时等关联变体可以切换，未解锁版本仍保持问号和隐藏主图。
- 加速度、阻尼等底层详细数值继续放在资料站详细数据中，避免把正文恢复成长篇机制参数表。

## 6. 卡面与卡背美术

本节以第 20 号文档为准，覆盖对话早期的不同提案：**不采用先前提出的 768×1024 竖长卡规格，不给三个主类铺不同纸底色，不提前选定铜角风格。**

- 收藏母版 2048×2048，展示导出 1024×1024；透明画布内保留三种实际外轮廓。
- 统一浅暖灰纸底、极轻上亮下暗渐变。纸底不透明，轮廓之外透明。
- 不再套统一的大矩形外框，以免遮住三主类差异。
- 主体清楚、占主要视觉空间；框线、低对比纸纹和边饰不过度抢眼。是否突破内框按最终分层规范处理，不擅自破坏外轮廓。
- 投射物主图应与实际弹体一致；普通及载荷变体主体位置大小一致。
- 右下角仅为适用基础载体添加碰撞载荷／定时载荷／被击破载荷角标。爆炸附效、火药引线不因此获得载荷角标。
- 卡名、属性、标签由 UI 绘制，不烘焙进纹理；中英文共用美术。
- 卡背轮廓与正面完全一致。建议交叉法杖共同纹章，配低对比纤维、压印、织线般符文和磨损；三类边饰协调，可加入少量对应法术的小印记。
- 类别装饰不暗示月亮／暗影阵营或稀有度。卡背可以共用母版，不要求每张从零重绘。
- 物品栏、地面版分别简化和投影，不能把鉴赏版直接缩小作为最终小图。
- 检查时火花旧运行卡图约 230×172、主体小图 64×64，直接放大不满足鉴赏目标。此为检查时样例，不代表全部源素材尺寸相同。
- 边框候选仍为墨线羊皮纸／古籍铜角／荆棘刻纹，没有默认获选；先对比三种用途后选择。

## 7. 收集记录规则提案（尚未由用户逐项确认）

建议使用「当前世界内，该玩家曾获得」：

1. 散卡进入物品栏、背包或鼠标手持位置时登记。
2. 获得装好法术的法杖时登记杖内卡牌，含出门杖。
3. 仅在地面看见、打开公共箱子看见、看见队友施法不算。
4. 不消耗卡牌；丢弃、分解、安装后不撤销收藏。同法术只计一次，独立载荷变体各自计数。
5. 玩家可通过实际交换卡牌补全收藏；共用书本显示各自记录，不把书当作记录容器。
6. 世界内记录跨死亡、重连、换角色、地面与洞穴迁移保留；新世界重新开始。需测试验证，当前并未实现。
7. 旧世界首次启用时补录当前散卡、背包和法杖内卡；过去拿到又丢掉的卡无法凭空恢复历史。

开发补充：以稳定法术 ID 保存收藏，不使用单张卡 UID、数组下标或当前排序。总数按当前公开可获得卡表计算，退役卡迁移和新增卡计数需设计版本兼容；服务端确认收集，客户端展示。不得用打开 UI 时全世界扫描物品来统计个人历史。

## 8. 实施阶段与验收建议

1. 对照第 20 号文档核对逐卡主类、标签、范围、角标和公开收集资格，维护共用元数据；缺失分类报错，不静默归基础法术。
2. 选定边框风格，制作三类各一张代表卡、三种卡背及一本收集册的样板。验证正面、背面、侧边和旋转，再批量制作。
3. 实现三页界面和详情，接入收藏记录、迁移、网络同步与中英文。
4. 批量美术接入与实机验证，先同步本地测试，不自动发布。

性能建议：网格静态，仅选中卡播放鉴赏动画；大图按需使用，先验证引擎实际加载行为，避免承诺未经验证的按需显存释放。只同步收藏变化，不持续发送整本数据。

验收包括：

- 三类轮廓在大图、小图、灰度下可分辨，纸底统一；透明边缘无压缩色边，背面无镜像文字。
- 小屏、不同 UI 缩放及中英文长名称不遮挡；返回后保留页码和筛选。
- 未收集卡不能通过悬停、搜索、关联变体泄露隐藏名称、主图和说明。
- 拾取、制作、堆叠拆分、鼠标取卡、背包装卡、预装法杖、出门杖和旧存档补录正确；反复获得不重复计数。
- 双人交换分别登记；仅查看箱子不登记；书本借出不转移进度。
- 重连、换角色、死亡及地面／洞穴迁移保持记录；联网收到新收藏时 UI 正确刷新。
- 打开书不暂停联机世界；建议受击自动关闭，并恢复输入焦点。控制器和键鼠交互需一并考虑。
