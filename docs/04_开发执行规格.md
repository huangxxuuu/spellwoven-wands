# 法杖 Mod 开发执行规格

> 实施变更（0.5.0-prototype）：用户已要求取消长按连射、点击缓冲与移动中强制施法。当前输入规范为右键单击检查资源，通过后使用客户端／服务端原生 attack 状态；失败静默且不排队，移动按原生规则打断前摇。本文旧设计中涉及连射的要求由此替代。当前完成范围见 README，复测以 05 为准；下文保留原设计基线，不表示全部已实现。

版本：设计基线 v0.2。范围：文档细化，尚未实施。本文把现有玩法转换为可执行任务、数据契约与验收条件；数值是首次实现的起点，不是已验证平衡结果，也不是 Noita 原版数值。

## 文档使用与需求边界

阅读顺序：01 了解成品体验；03 理解抽牌和运行时外观；04 按任务实施；02 用作架构和本地源码索引。抽牌语义以 03 为准，04 补足接口与边界。如果实现发现两者冲突，先修正文档与用例，再提交实现，不能悄悄改玩法。

用户明确要求：DST 联机；多种随机属性法杖；子弹、弹道、特殊效果法术；参考 Noita 的乱序、多重、回绕与缺蓝处理；杖头、杖身、杖尾运行时组合；外观反映乱序、多发和容量；本轮仅规划。

本基线采用的建议值：六类生成倾向、24 卡、2—12 格、四阶、工作台编辑、无耐久、PvE 无友伤、默认不点燃环境、键鼠首发。它们是可调整的实现默认值，不标记成用户逐项确认的要求。手柄完整编辑导航、地形破坏、刷新环、复制系列、玩家手动改装外观不在本次首版任务中。

当前没有阻止继续细化的产品信息缺口。仍须实际验证的技术条件为：工具链运行、手持部件跟随与遮挡、分层库存图标、角色动作与连射、跨分片持久化。每项都有 P0／P1 通过标准；在验证前不批量制作最终素材。

## 目录与模块职责

开发时新建 mod/ 保存可安装内容，assets_src/ 保存美术源文件，tools/ 保存资源构建和安装辅助脚本，tests/ 保存纯逻辑测试，test_reports/ 保存运行记录；当前不创建上述实现文件。游戏目录只作为接口参考和独立测试安装目的地，不改原版文件。

## 数据契约

时间统一秒，坐标使用 DST 世界坐标，速度为世界单位／秒，角度统一度；动画源坐标使用像素，单独保存到游戏缩放比例。schema_version、generator_version、appearance_schema、protocol_version 分别管理，不能用一个版本号代替所有迁移。

### 法杖持久状态

| 字段 | 类型与约束 |
| --- | --- |
| uid | 字符串；世界命名空间＋分片命名空间＋持久递增计数，禁止用临时 GUID 代替 |
| schema_version、generator_version | 正整数；初版均为 1 |
| archetype、tier | 定义表枚举；tier 1—4 |
| seed、rng_state | 独立随机流状态；生成与洗牌使用不同流 |
| stats | capacity、mana_max、mana_regen、cast_delay、recharge、draw_count、spread、shuffle |
| always_cast | 空或白名单法术 ID；不占卡槽 |
| cards | 长度等于 capacity 的槽数组；空槽使用 false，避免 Lua 稀疏数组长度歧义 |
| card record | card_uid、spell_id；首版不消耗次数、不堆叠实体；保留未知版本原始记录用于恢复 |
| appearance | head_id、body_id、tail_id、detail_id、length_class、appearance_schema |
| runtime | mana、deck、discard、reload_delta、remaining_cast、remaining_recharge、rng_state |
| config_revision | 编辑／属性变更时递增；正常扣蓝不递增，避免编辑快照频繁失效 |

deck/discard 保存 card_uid，不能只存 spell_id，因为相同法术可能存在多张。提交边界处每张装入卡必须恰好出现于一个牌区；当前手牌在预载事务结束后清空。存档没有实体引用和绝对系统时间。uid 在交易与分片传递时保持不变，生成新卡才分配新 uid。

### 核心接口

| 接口契约 | 输入 | 输出与副作用 |
| --- | --- | --- |
| GenerateWand | seed、tier、archetype、definitions | 完整属性与外观记录；不创建实体 |
| CompileCast | 法杖状态副本、卡定义、limits | 新状态、CastPlan、trace，或错误；不修改原输入 |
| ReserveBudget | caster_uid、cast_id、所需额度 | token 或错误；只操作预算管理器 |
| CommitCast | 原状态版本、编译结果、budget token | 一次提交法力、牌区、冷却；成功后交给 executor |
| ExecutePlan | CastPlan、owner、origin、direction、token | 弹体句柄；创建失败清理所有已创建对象并执行失败补偿 |
| GetSnapshot | 玩家、法杖、用途 | 所有权校验后的有限数据视图 |
| BeginEdit / CommitEdit / CancelEdit | 玩家身份由引擎提供，消息参数见协议 | 租约或事务结果 |
| Save / Restore | 持久数据 | 校验、迁移、恢复；不重新随机生成 |

CastPlan 包括 cast_id、root_block、payload_blocks、projectile_count、reserved_count、mana_spent、cooldown、next_state、warnings。块包含 modifiers、projectile descriptors、local_delay；触发器描述引用块 ID，不引用运行中的法杖组件。trace 仅开发模式记录取牌来源、缺蓝跳过、回绕和块归属。

ExecutePlan 创建实体期间先将对象置为未激活，不执行碰撞、伤害、声音或触发。全部创建成功后统一激活；激活前失败才能恢复本次提交前的法力、牌区和随机状态并清理额度，同时留下失败冷却。一旦已有真实伤害发生，不得再回滚费用以产生免费伤害；激活后的单个异常记录日志并清理该弹体。施法提交与激活处在同一不让出的服务端调用内。

## 确定性的属性生成 v3（0.25.1）

不再使用属性点或总预算。先确定稀有度与类型，再分别按离散截断正态权重抽取属性。候选值权重为 `exp(-0.5*((x-中心)/标准差)^2)`，只对合法候选归一化，不把越界值压到端点。随机流使用 Park–Miller；同种子、阶级、类型和生成版本可复现。

全局兼容边界包含旧存档和固定入门杖；新随机杖使用下面更窄的分阶范围。旧杖不重抽，继续保存原有数值、卡牌、名字和外观。

| 属性 | 全局下限 | 全局上限 | 新生成精度 |
|---|---:|---:|---:|
| 容量 | 2 | 12 | 1 |
| 法力上限 | 24 | 1200 | 5 |
| 回蓝 / 秒 | 2 | 320 | 1 |
| 施放间隔 / 秒 | 0.08 | 2.4 | 0.01 |
| 充能 / 秒 | 0.1 | 6 | 0.01 |
| 散射 / 度 | 0 | 15 | 0.5 |
| 基础同发 | 1 | 6 | 1 |

SAN 转化率固定 20；乱序为布尔值。新生成的施放间隔不低于 0.20 秒，避免低于当前施法逻辑下限的无效收益；卡牌修正后的充能时间仍可以降到零，实际速度还受原版动作约束。

每格格式为 **下限～上限；中心 / 标准差**。中心是类型修正前的分布峰值，不是截断后样本的精确均值。

| 容量 | 3～7；5 / 1 | 4～9；6 / 1.15 | 6～11；8 / 1.15 | 8～12；10 / 1 |

## 施法解释器的逐步执行

1. 检查法杖 ready、装备所有权、角色可施法状态和冷却；按世界时间结算法力恢复。
2. 复制 runtime、随机流和计数器，建立空根块。执行固有效果，然后按基础 draw_count 发起不允许回绕的外层抽取。
3. 每次抽取：取牌库顶；缺蓝则直接放弃牌堆并继续当前抽取，不执行卡片效果、不占有效抽取名额。实际成功卡移到手牌，扣蓝，累计该卡的费用与回充增量。
4. 子弹加入块描述；修饰更新块并以允许回绕模式抽一次；多重以允许回绕模式抽 N 次；触发器加入载体并递归建立子块。所有卡使用同一手牌区，块的参数状态独立。
5. 仅当本次抽取允许回绕、牌库空、弃牌堆非空且尚未回绕时，回收弃牌堆并排序／洗牌；设置 wrapped。再次遇到空牌库且不能回绕时正常结束该次抽取，不把“不足 N 张”视为错误。
6. 完成整次预载后给各块中的投射物应用最终修饰、展开散弹的实体数量并统计载荷树。所有手牌转弃牌；若 wrapped 或牌库空则确定回充时长并准备下轮牌库，清零本轮回充累计值。
7. 校验抽取次数、执行节点、触发深度和实体额度；正常结果原子提交。超限丢弃临时结果，施加 0.30 秒失败冷却。全空或全缺蓝是正常空施法，不是网络错误，进入回充避免请求空转。

无卡可付费时无需无限扫描；在允许的一次回绕后再次无法取得有效卡即可终止。每个实际执行实例计入 32 节点上限，缺蓝跳过只计入 128 次尝试上限。根块深度为 0，最多建立深度 2 的载荷块。单次新增上限 12 按整棵载荷树的最大总生成数计算，预留额度随后只转换、不重复增加。

CastPlan 生成后不得再从源法杖读取卡组。玩家切换或丢弃法杖不会取消已经付费的普通飞行弹，但角色死亡、断线或转分片取消其未执行载荷及持续施法；飞行弹可继续视觉移动，失去有效攻击者时不再造成伤害并尽快清理。

载荷扇形方向以触发时载体最后有效切线为准，生成点离碰撞中心向前偏移 0.2。载荷可以再命中触发载体命中的敌人，但沿各自弹体的命中名单只结算一次；它们是独立攻击。纯墙体碰撞不触发“命中触发弹”，与其法术说明保持一致。

## 输入与角色状态

键鼠默认方案：装备法杖且 HUD 未抢占输入时，右键地面开始／持续施法，松开停止；可配置独立施法键代替右键。检查法杖提供只读属性入口，靠近工作台时交互按钮打开编辑；聊天、暂停菜单和编辑界面中禁用施法输入。实际输入 hook 名与动作注册参数在 P0 核对，不把新键绑定到全局不受控回调。

角色流程：READY → AIMING → CAST_RECOVERY → READY；另有 EDITING、DISABLED。服务端控制实际发射时间和最低间隔，客户端只提前显示瞄准反馈。移动取消持续施法；受击、死亡、骑乘状态改变、装备切换、界面打开均发送停止并由服务端再次校验。骑乘施法列入首版验证，若动作接口不支持须明确记录阻塞，不静默宣称支持。

先复用合适的原版施法姿态，建立受控施法状态；每次发射在定义好的动画事件点执行。若复用动作无法达到 0.20 秒间隔，P0 要调整动画方案或显式提出频率修改，不能只让伤害发生而完全跳过表现。连射由服务端任务推进，不靠客户端每颗子弹发送 RPC。

## 网络协议与状态同步

协议版本初值 1。所有客户端字段不可信；身份取引擎回调中的 player，不接受消息中的玩家身份。法杖通过当前实体 GUID 定位，再校验持久 uid、所有权和 config_revision；持久 ID 本身不是访问凭据。

| 消息 | 主要字段 | 验证／结果 |
| --- | --- | --- |
| CAST_START | seq、wand_guid、wand_uid、aim_x、aim_z | 装备与角色状态有效；启动施法意图，返回接受／拒绝 |
| AIM_UPDATE | seq、aim_x、aim_z | 只更新有效施法会话；有限数值、射程和地图条件 |
| CAST_STOP | seq | 幂等停止；延迟的旧 seq 不得重启施法 |
| INSPECT | request_id、wand_guid | 自身库存或可检查距离内物品；返回属性快照 |
| EDIT_BEGIN | request_id、wand_guid、workbench_guid | 距工作台不超过 4，法杖在自己库存；返回 session_id、revision 和卡清单 |
| EDIT_COMMIT | request_id、session_id、revision、slot_card_uids | 租约、卡所有权、重复 UID、容量、快照版本都合法；返回新 revision |
| EDIT_CANCEL | session_id | 幂等清理草稿会话 |
| SNAPSHOT_REPLY / EDIT_REPLY | request_id、revision、payload／error_code | 客户端只应用匹配请求与会话的结果 |

施法意图每 0.25 秒更新一次；服务端 0.75 秒未收到有效续期即停止，防止丢失松键消息导致永远连射。start/aim 合并每玩家每秒最多 10 次、突发 15；stop 总是能停止当前会话，不被普通限流卡住。编辑开始每秒最多 2 次、提交每秒 2 次，检查每秒 5 次。实际发射仍由法杖冷却限制。

服务端拒绝 NaN／无穷坐标，并以当前施法者位置重新计算方向和最大范围；客户端裁剪只为操作体验。施法起点由服务端玩家位置与固定发射偏移决定，不接受客户端提供的任意出生点。目标合法性在生成和命中时分别检查。

小型复制状态：容量、外观版本化描述、是否 ready、当前法力显示、施法序号、装备表现关联。属性／外观必须为晚加入可恢复的状态，不能只发一次事件。外观描述优先单条有界快照打包，容量与外观校验一致后显示；如底层字段大小不足再分块，不能假定 net_string 可任意长。P0 检查可用网络类型与大小。

完整卡组通过按需回复发送，逻辑有效负载上限 8 KiB、卡记录不超过 12；在实际 API 限制更小时按不超过 512 字节分块，含 snapshot_id/index/total/revision，总块数最高 16，2 秒超时丢弃部分结果并允许请求一次新快照。不得将半份快照当成完整状态。

法力显示每秒最多 4 次同步并在扣蓝时及时刷新；UI 插值不影响权威扣费。待冷却显示以剩余时长校正，不比较不同机器的绝对时钟。客户端如无确认，不自行生成伤害弹体。

错误码至少包括 NOT_READY、NOT_OWNER、INVALID_STATE、OUT_OF_RANGE、STALE_REVISION、SESSION_EXPIRED、CARD_MISSING、DUPLICATE_CARD、INVENTORY_FULL、RATE_LIMIT、COMPILE_LIMIT、PROJECTILE_LIMIT、PROTOCOL_MISMATCH。每码对应中文提示；缺蓝跳过属于 trace／warning，不把整次施法标记成失败。

## 卡片生命周期与编辑事务

卡片实体不可堆叠，拥有独立 card_uid。装入法杖后转为数据记录，不保留隐藏库存实体；取出时按记录重新生成卡片实体，并保持 card_uid。未知法术数据转换为可取出的“失效法术卡”，保留原 ID 与字段，不能直接删除。

编辑租约有效 30 秒，界面每 10 秒续期；玩家离开工作台范围、法杖移出库存、死亡、断线立即失效。租约期间该杖不能施法，但不锁死玩家整个库存；提交时重新校验卡片是否仍在其可用库存或装备背包内。外部容器和鼠标拖拽中的卡首版不能用作提交输入，UI 提示先放回背包。

提交分为：校验 → 计算净装入／取出 → 规划取出卡片的空位（包括本次装入释放的格子）→ 创建不可见临时取出实体 → 暂存装入实体并记录原槽位 → 写法杖记录与新牌区 → 放入取出实体 → 删除已装入原实体 → 提升 revision → 回复。全程不让出执行权，不产生存档中间态；失败清理临时实体并恢复原槽位与法杖状态。实际引擎库存回调可能重入，因此服务端需要短事务锁与回滚日志，P1 专门验证。

背包无法容纳取出卡时拒绝整笔提交，不在地上静默丢卡。只重排法术不创建／删除实体。成功编辑重置牌库，但保留现有冷却并施加至少一个基础回充时间，取较长值；法力保留，避免通过反复编辑刷新冷却或回满蓝。

同一连接会话内以 player_uid＋request_id 缓存最近 64 次结果，保留 60 秒；重试返回原结果，不再次创建卡。重连后旧 session_id 失效，客户端重新获取快照，不跨连接重放旧提交。

## 弹道、碰撞和伤害实现要求

服务端以模拟 dt 推进，客户端只显示表现。每步计算中心轨迹、局部曲线和实际新位置，再对上一位置到新位置做扫掠。曲线跨度大于 0.5 时细分，最多 8 段；仍不足时限制本步位移，不能悄悄穿过障碍。

候选集使用围住扫掠段的查询区域，筛选有有效战斗／生命组件的实体；按沿路径首次交点排序，同距离按稳定实体序排序。目标半径从实体物理信息取得，缺失时使用类型默认半径；不能只用目标中心点判断命中。每弹保存已命中目标 GUID，默认命中施法者及友方无效。

墙体和阻挡物使用可解释的几何碰撞近似，法线来自最近碰撞点；无法得到可靠法线时销毁，不猜随机弹跳方向。海岸及不可通行区作为不可反射边界处理。艇上施法、海岸边界与墙角列为集成测试项，P0 核对实际地图与物理查询接口。

伤害适配器负责攻击者归属、目标防御、仇恨、击杀与有效伤害统计；不得统一直接减 health 绕过 combat。吸血使用实际生命损失且剔除无敌目标与过量伤害。PvP 同时要求世界允许 PvP 且服务器开启本 Mod 友伤；随从按 leader 归属过滤，友伤关闭时禁止旁路范围伤害。

默认灼烧使用独立有归属的持续伤害，不点燃建筑。危险点火模式默认关闭，启用后仅通过合法燃烧组件作用于命中的可燃目标，火传播遵循游戏机制；必须在设置说明中明确会产生环境后果，不将此模式纳入默认平衡。

弹体移除无论来自超时、碰撞、保存退出、玩家消失还是资源失败，都走同一清理入口：取消任务、释放预留、移除视觉、清空引用。每个清理操作幂等。正常超时可执行一次终止爆炸；管理员清理、预算失败补偿和断线取消不得产生额外爆炸伤害。

## 存档、分片与恢复

保存前结算法力和剩余冷却，不保存正在运行的任务句柄。分片迁移时携带法杖和卡片的完整记录，保留 uid 与随机状态；目标分片先 Restore，成功后置 ready，不把恢复实体误当新生成实体。所有权引用迁移后重新建立。

损坏牌区的恢复规则：若 cards 完整但 deck/discard 重复或缺项，记录诊断，按 cards 重建新轮牌库并施加基础回充，不重抽属性。非法数值夹取定义允许范围，非法外观映射到同语义默认部件；不可映射的缺资源保留原 ID 并显示兼容占位，不覆盖存档以免丢失恢复机会。

活动弹体和载荷不保存；世界关闭后不补发、不返还已成功提交的施法费用。编辑事务不得跨存档，保存边界只看到提交前或提交后数据。恢复、迁移、回滚后计数器不得与仍存活物品 UID 冲突，检测碰撞并记录，不仅依赖机器时间生成 ID。

## 验收矩阵与失败诊断

| 组 | 必测内容 | 证据 |
| --- | --- | --- |
| R 规则 | 03 用例逐例；基础多发不回绕；缺蓝不耗抽取名额；当前手牌不可回收；修饰全块；父子块隔离 | 输入状态、固定随机种子、trace、期望／实际 |
| G 生成 | 10,000 样本；预算不超；六类型；固有概率；外观与属性匹配 | 分布报告，不把“全部合法”等同于已平衡 |
| E 编辑 | 满包、外部移卡、租约过期、同卡重复、旧版本、回复丢失重试、连点 | 前后 UID 清单、事务日志 |
| N 网络 | 本地主机与两远端、专服、100/200 ms 延迟、晚加入、失联、重复序号 | 客户端／服务端日志和录屏；测试故障注入只在独立环境 |
| S 存档 | 保存重启、掉落、死亡、背包、地面↔洞穴、回滚、未知卡 | 保存前后规范化数据比较 |

| P 性能 | 1/2/4/6 玩家，30 分钟循环施法 | 平均／p95/p99 帧耗时、实体数、网络量、内存趋势 |

性能目标沿用 02：六人负载 p95 帧耗时较同世界空载增加不超过 5 ms，按具体硬件评估。暂停施法并等待所有寿命结束后，活动弹体、预留额度与残留表现应回到基线；每次打开关闭编辑器不得增加常驻监听数量。

日志使用 NW 前缀，记录 uid、cast_id、request_id、error_code，默认不逐帧刷屏。开发开关可导出取牌轨迹和预算计数，发布默认关闭。每次游戏更新重新核对版本与关键适配层；当前 760178 是调研基线，不是永久兼容承诺。

## 开发启动时的第一步

实施从 T00 开始，随即验证 T01 的工具链、组合手持和库存图标。无需等待完整素材或最终平衡数值。三项关键资源验证中任何一项失败，都先报告具体接口或表现问题并修正方案；不默认退回全组合预生成，不自行删去用户要求的运行时部件组合。
