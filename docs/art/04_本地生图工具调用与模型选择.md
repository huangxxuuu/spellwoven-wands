# 本地生图工具调用与模型选择

整理：2026-11-14；模型建议依据2026-11-10记录。每次新的生图、重绘、参考图/蒙版编辑任务完整读取本文；它与共同规范和对应类别规范一并生效。

## 工具路由

优先调用 `D:/Projects/AI/open_xiaoai/local-imagegen/imagegen.py`，直接连接 OpenAI 官方 Images API。脚本在本机执行，模型生成在服务端执行，消耗用户的 API 额度。

仅在以下任一条件满足时使用内置 image gen / image_gen 插件：

1. 用户明确要求本次使用 image gen 插件。
2. 已确认此工具使用的 OpenAI API 额度耗尽。可以直接切换插件，无需再次询问许可，须告知用户原因并记录依据。

必须区分额度耗尽与暂时故障。可用依据包括服务端明确的 `insufficient_quota` 或余额/额度不足信息、账单明确显示可用额度耗尽、用户明确确认额度耗尽。普通 HTTP 429 也可能只是速率限制，不能单凭状态码触发切换。达到某项预算限制是否阻止请求，应以服务端实际返回为准。

401、403、超时、网络错误、服务端临时错误、参数错误、内容拒绝、Key 或依赖缺失、工具路径失效、画质不满意都不是额度耗尽。先修复可恢复问题；无法继续时报告具体阻碍，不擅自切换插件。超时请求可能已执行并计费，不盲目重试。

用户的项目工具选择优先于通用技能默认值，不能因 imagegen 技能默认推荐内置工具或自带 CLI，就绕过本工具。切换插件时仍须执行项目的美术规范和验收。

## 最小调用契约

- Python：`D:/Projects/AI/open_xiaoai/local-imagegen/.venv/Scripts/python.exe`；脚本：`D:/Projects/AI/open_xiaoai/local-imagegen/imagegen.py`。在项目根目录 `D:/Projects/AI/dst_mod` 调用，无需在命令中传 Key。
- 先保存实际完整 UTF-8 Prompt；生成用 `generate --prompt-file`，保留现有身份/结构或局部修改用 `edit --prompt-file --image`。先实际查看每张参考图，按Prompt图号顺序传入并写明画风、身份、构图或材质职责。
- 显式选 `--model`、尺寸、质量和背景；尺寸服从任务，生成源图不等于运行贴图。透明背景用 PNG/WebP，JPEG不支持透明。蒙版为与第一张图等尺寸、低于4 MB的PNG，完全透明区域表示编辑区。
- 每张参考图须为非空 PNG/JPEG/WebP、低于50 MB；当前脚本最多16张，仅保留有职责的参考。不要为省费删除必要身份参考。
- 总是显式指定项目内输出。单张用 `--output`，拒绝覆盖图片或记录，迭代换文件名；多张用 `--output-dir`，同Prompt候选用 `--n`，不同Prompt分次调用。
- stdout成功返回JSON路径与usage，进度/错误在stderr，失败退出码非零。默认超时600秒，可用 `--timeout 900`，SDK自动重试关闭。超时可能已计费，先查记录再决定是否重试。
- 首次调用、依赖修复、dry-run、完整生成/编辑/蒙版/批量命令及输出记录细节，按需读[完整用法与历史成本](reference/context_20261114/本地生图完整用法与历史成本.md)。示例只用于调用方法，不替代本次Prompt。

## 模型选择建议

以下为 2026-11-10 查询的官方定位与本项目选型建议，不是同场实测的画质排名。此次账号模型列表包含下列系列，但实际请求仍以项目权限和服务端响应为准。

| 场景与优先级 | 模型 | 使用建议 |
| --- | --- | --- |
| 精细编辑优先 | `gpt-image-2.6-sunburst` | 复杂部件、严格保留比例与连接、多参考图分工、要求局部修改时优先测试。 |
| 日常迭代优先 | `gpt-image-2.6-flare` | 文本生图、探索方案、需要快速反复调整时优先测试。 |
| 上一代精度对照 | `gpt-image-2.5-sunburst` | 适合作为精细改图对照，不能仅凭版本号判定它弱于 2.6 Flare。 |
| 已验证的项目基线 | `gpt-image-2.5-flare` | 奥术台已完成三次真实调用，可用于比较新模型的费用、耗时和风格保持。 |
| 旧工作流对照 | `gpt-image-2` | 灵活尺寸、高保真参考图输入；已有方案效果合适时可保留。 |
| 旧模型 | `gpt-image-1.5`、`chatgpt-image-latest` | 官方已标记 Deprecated，不作为新任务默认值；后者指向 ChatGPT 曾使用的快照，不能认为它等于当前 image gen 插件。 |
| 旧款成本优先 | `gpt-image-1-mini` | 可用于简单草稿成本对照，但也已标记 Deprecated，不作为复杂结构保真的首选。 |

当前脚本内置默认模型为 `gpt-image-2.5-flare`。项目调用建议显式传 `--model`，确保使用本次选定的模型。

带日期的模型名是固定快照，不是额外的性能档位。比较模型时保持 prompt、参考图顺序、尺寸、quality 和输出格式相同，再观察结果与 usage；不凭某次单图得出绝对优劣。

质量建议：草稿从 `low` 或 `medium` 起步，部件多的最终候选考虑 `high`。2.5/2.6 系列还支持 `xhigh`、`max`，仅在细节确有需要时使用。更高细节不一定更符合饥荒的大色块与稀疏材质笔触。固定质量和尺寸便于比较成本，`auto` 会增加变量。

2.6 的 `complexity` 与 `quality` 是不同设置，但当前本地脚本没有暴露 `complexity`、markup、SVG 或 GIF 参数；不要在命令中虚构这些选项。需要此类能力时先维护并验证工具，不能直接认定应改用插件。

本角色的文本模型不是生图模型配置；不得擅改本地工具的模型默认值。模型表是带日期的选型建议，账号权限和实际服务端响应优先；新预算承诺前重新核对官方价格，历史成本不是当前余额。

## 生成后检查与记录

查看每张源图，检查剪影、支撑连接、部件数量、比例、符号、材料画法和裁切。透明图除读取 Alpha，还应实际合成到白色与灰色背景检查边缘；不能把完全透明像素中的 RGB 颜色误判为可见光晕。

按对应类别在目标观看尺度验收。实际 prompt、参考图路径、模型、参数和 usage 与源图一起保存；原始返回图和派生预览分开。涉及接入游戏时才进行编译与实机验证，未做的验证须如实说明。

如果因额度耗尽转用插件，记录错误依据和工具切换，不伪造插件 token 消耗，不把 API 的实测费用直接套给插件。内置插件的具体模型没有在当前接口中公开，不能声称两者相同。
