# 客户端复测：原生单击施法

本文记录 0.5.4 的历史测试。从 0.8.5 起的长按、移动优先和理智扣费测试请见[当前测试指南](11_法术卡测试指南.md)，发布包中对应 TEST_GUIDE.md。

适用版本：**0.5.4-prototype**。本轮优化多弹移动、碰撞查询、法术就绪计算及界面重复刷新。保留火魔杖的提交发射时点和移动取消后摇。继续禁用长按连射、点击缓冲、回蓝后自动补发和自定义快速施法状态。只有新的一次右键点击会尝试施法；失败静默。动作使用游戏原生攻击状态和原生速度，法杖冷却与原生攻击间隔都需要满足。

0.5.4 射程调整：四种可用弹体的基础寿命乘以 1.5，最大飞行距离与鼠标瞄准距离提高到 30。速度沿用 0.5.3。无修饰火花／魔箭／散弹／重弹的理论最大飞行距离分别为 21／30／14.625／18.375；请检查更远处的目标可命中、超过最大射程的目标不会被击中，并复测多弹流畅度。加速／减速修饰继续生效，伤害、耗蓝与冷却沿用原设置。

## 本轮优先：整体卡顿与多弹

请先复测原来会卡顿的“三重 + 三四颗弹”配置，在同一个地点、相同镜头与其他 Mod 配置下比较。观察人物、镜头和弹体，不只观察子弹本身。

| 编号 | 操作 | 预期与反馈重点 |
| --- | --- | --- |
| P1 | 单弹与三重交替施法，期间移动人物、转动镜头 | 不因多发而出现明显整局停顿；分别记录人物／镜头／弹体是否仍不流畅 |
| P2 | 在空旷地面及基地杂物较多处分别重复 P1 | 检查场景密度是否仍明显影响卡顿；测试不需要拆除现有建筑或清理物品 |
| P3 | 原有三四弹配置稳定后，再试三重散弹（有三张散弹时可组成九弹） | 不明显掉帧；弹体过期后应消失，不越打越卡。卡片不足可跳过九弹，不必额外领取 |
| P4 | 用短中长杖朝四周施法并旋转镜头 | 弹体仍从杖头附近出现、保持高度与原尺寸，不落到脚底；无重复图案或遗留图片 |
| P5 | 对测试靶发射单弹和多弹，再向墙后目标发射 | 正常扣血，墙阻挡；同一颗普通弹不重复伤害。不要用玩家或随从测伤害，它们受保护 |
| P6 | 重复施法、换卡、缺蓝后回蓝，再保存退出重进 | 新法术立即生效；回蓝足够后新点击可施法；没有缓存导致的旧卡、长期假冷却或错误耗蓝 |

本轮弹体增加高度网络字段，务必完整重启游戏及房主世界，不能热更新。服务器物理实体沿地面移动，本地图片保持杖头高度；无渲染专服已验证网络高度与移动，但实际画面需要 P4 检查。

## 优先检查：输入和移动

先装备 spark，法力足够、冷却结束，关闭编辑面板，在宽阔地面测试。每次点击之间松开右键。

| 编号 | 操作 | 预期结果 |
| --- | --- | --- |
| H1 | 静止时单击右键，朝不同方向各试一次 | 一次动作、一发子弹；人物朝向目标，子弹从杖头附近出现 |
| H2 | 就绪时按住右键 5 秒不松开 | 只触发起始点击的一次施法；冷却结束后也不连射 |
| H3 | 执行 `nw_saveprobe()`，冷却期间点击或一直按住右键，等冷却结束 | 不空挥、不说“我做不到”；结束时不补发，需要松开并重新点击 |
| H4 | 执行 `nw_manaprobe()` 清空法力，立即按住右键直到回蓝足够 | 不空挥、不扣除刚回复的蓝；回蓝后不自动施法，松开并重按才施法 |
| H5a | 点击后极早移动，在提交发射前取消前摇 | 不出弹、不扣蓝，人物继续移动；没有稍后补发或位置回拉 |
| H5b | 停步、单击施法，稍抬手后立即移动；与原版火魔杖对比 | 达到提交时点后，移动取消剩余收招动作，弹体继续飞行；不用等完整挥杖动画结束。既不退蓝也不多发 |
| H6 | 松开移动键后立即点击；另试鼠标左键寻路后点击右键 | 按原生动作与移动规则响应；没有 Mod 额外等待计时。记录是否仍需停步近一秒、滑步或回拉 |
| H7 | 前摇开始后打开编辑面板或换下法杖 | 本次待发射动作被取消或在发射时校验失败，不继续用旧杖出弹；关闭编辑器后新点击可施法 |
| H8 | 分别点击空地、测试靶或怪物 | 都按点击位置施法；不先跑到目标脚边，也不附加一次近战伤害 |
| H9 | double、wrap 分别多次单击，覆盖几轮回充 | 多重和回绕保持原规则；每次新施法都需重新点击，不依赖长按 |

性能复测后，可顺便复测 H5a、H5b 和 H6。动作没播完不一定还处于前摇：当前约第 7 帧（0.23 秒）提交发射，后续为可被移动取消的收招。H5a 必须在提交前打断；提交后再移动不会撤销弹体或退回法力。不要只凭看到弹体的时刻判断提交帧，显示还受网络与渲染影响。原生移动存在短暂动作保护及帧调度，重点是与原版同样的可打断行为和没有持续位置回拉，不要求同一帧取消。

`nw_saveprobe()` 只设置当前手持杖 30 秒诊断冷却。`nw_manaprobe()` 只把当前法力设为零，之后正常回复。为了更清楚观察 H4，可只装一张耗蓝 30 的重弹。缺蓝处理仍保留 Noita 式跳过：若后面的便宜弹能支付，就允许发射它；并非要求所有卡都能同时支付。

## 验证边界与反馈

自动测试已通过 Lua 5.1 规则检查和游戏 760944 版独立无渲染专服测试，包括原版火魔杖与本 Mod 均在第 7 帧提交的对照、发射后移动取消收招并保留弹体、原生动作选择器、原生攻击进入、移动打断不扣蓝、单击一次、禁止重复、缺蓝静默及恢复后不补发。它们不能证明图形客户端的鼠标输入、预测和网络回拉已经正常。

没有第二位玩家，可以先测试自己创建的联机世界，并记录“远端未测”；独立远端客户端、网络延迟、骑乘和洞穴跨分片仍待验证。当前仍是原型，不是完整首版，全部 24 种法术执行效果、正式配方等尚未完成。

本轮反馈建议：`P1 整局是否卡；P2 基地是否更严重；P3 九弹是否卡／跳过；P4 高度与图案；P5 命中；P6 换卡回蓝；远端未测。`

动作回归反馈可写：`H1 正常；H2 不连射；H3/H4 无空挥且不补发；H5a 提前取消结果；H5b 能否抬手出弹后移动／是否回拉；H6 停步立即点击结果；H8 正常；远端未测。` 移动问题请注明键盘走动还是鼠标寻路，最好附几秒录屏；崩溃保留报错与日志。客户端日志通常在文档目录 `Klei\DoNotStarveTogether\client_log.txt`，服务器日志位于对应存档 Master/Caves 目录。
