## 2. 版本与修复记录

### 0.25.12：128px 图标在物品栏溢出、凹口边框缺纹理

用户发现卡牌在法杖编辑框里正常，在原生物品栏里整体放大溢出。根因是原生物品栏通过网络数字哈希传递图集标识，而先前的适配只识别字符串路径。

[`card_icon.lua`](../mod/scripts/nw/card_icon.lua) 同时识别图集路径和已解析路径的哈希，将这些资源的原生 UI 显示尺寸设为64单位；法杖编辑框仍可自行指定尺寸。**纹理源仍是128×128，不应通过降回64px纹理来修复显示尺寸。** 图集为2048×2048。

施法控制卡顶部凹口两条竖边的纹理问题通过边缘平行内缩修复；不要恢复按中心整体缩放、覆盖凹口竖边的画法。相关入口为 [`compose_spell_cards.py`](../tools/compose_spell_cards.py) 和 [`test_card_icon.lua`](../tests/test_card_icon.lua)。

### 0.25.13：四张独立调音卡

已注册 `pitch_octave_up`、`pitch_octave_down`、`pitch_semitone_up`、`pitch_semitone_down`，分别偏移 +12、-12、+1、-1 半音；均为普通修饰卡，耗蓝1、额外延迟0。放入奥术台音符法术分类，以空白卡、芦苇、树枝或木炭低成本制作。旧卡编号保持稳定；可玩卡面增至186张。

同组调音相加、升降抵消，载荷独立计算；加速／减速不再改变音高。基础弦琴 C 的音高同步为 C4。入口：[`pitch_modifiers.lua`](../mod/scripts/nw/pitch_modifiers.lua)、[`compiler.lua`](../mod/scripts/nw/compiler.lua)、[`acquisition.lua`](../mod/scripts/nw/acquisition.lua)。

最初采用临时音源的音域限制已被另一对话的正式76个单音素材覆盖，**不要恢复临时 C3–B5 音域或旧的加速／减速调音设计**。当前陶笛 G#3–A#6、弦琴 G#2–G#5，包含半音；越界静音但法术效果正常，具体音频状态以第22号文档和最新代码为准。

### 0.25.14：拿卡指向地面卡时没有“叠放法术卡”提示

原版 `AddComponentAction` 对同一个 Mod 的“动作类型＋组件”只保留一个回调；后注册会覆盖先注册。

叠牌与粉尘修复法杖都曾注册在 `USEITEM / inventoryitem`，后者覆盖前者，因此连提示也不会出现。现将叠牌注册在法术卡本身已有的 `USEITEM / stackable`，保留修复入口。

入口：[`cardpile.lua`](../mod/scripts/nw/cardpile.lua)、[`wand_damage.lua`](../mod/scripts/nw/wand_damage.lua)、[`test_cardpile_actions.lua`](../tests/test_cardpile_actions.lua)。针对测试先复现覆盖，再验证两个动作共存，含满堆、鼠标左右键和 INLIMBO 限制。牌堆容量仍为25个真实卡槽，同名卡原生数量堆叠与牌堆容器是不同机制。

## 3. 0.25.15：用户确认的地面牌堆规则

### 四档厚度

| 实际卡数 | 上部 | 下部 |
| --- | --- | --- |
| 1 | 单卡真实轮廓 | 无底堆；牌堆剩1张时恢复单卡 |
| 2 | 两层真实轮廓 | 不虚构第三层 |
| 3 | 三层真实轮廓 | 无额外底堆 |
| 4–8 | 前三层真实轮廓 | 第四张起按有／无六边形选择2种模板 |
| 9–25 | 前三层真实轮廓 | 第四张起按无、仅1个、多个相邻、多个分隔选择4种模板 |

- 前三张按容器**前几个非空格子的实际顺序**读取，不从深处挑不同类别来展示，不改变玩家取牌顺序。
- 前三层中的 R、H、N 均保留真实轮廓；旧的“底层 N 一律视作 R”规则已被覆盖。凹口被上层自然遮住时，不强行画到上层之上。
- 下部是厚度与类别分布的概括，不承诺逐张还原第4–25张的顺序。
- 六边形适度向侧前方错开，露出连续 V 形斜边；仍是完整纸牌轮廓，不能画成矩形侧墙上贴一个三角。
- 用户特别纠正过：**“相邻／靠拢”模板的两个六边形必须直接相邻、横向对齐，中间不能夹一张矩形。** “分隔”模板则有矩形纸层隔开。
- 多六边形的两种变体由服务器创建时选择并保存，不因加减卡、刷新或读档反复随机切换。
- 地面纸牌应平放，玩家走过时显示在牌面上方。

### 最终素材结构：不使用198张整堆贴图

先前曾按全部组合导出198种牌堆，加3张配套单卡；用户认为过多，要求拆分运行时组合。最终方案进一步复用到：

1. 上部3张通用纸层：R／H／N，最多按顺序叠三层。
2. 下部6张模板：中档2种、厚档4种。
3. 另有3张通用接地阴影，按最底层轮廓选择。
4. 顶牌主图复用已有卡面，独立覆盖在共享动画的 `face` 符号上。

因此为 **9张主体素材＋3张阴影**。仍有201种布局，但只存图层引用、位置和绘制顺序，不存201张完整纹理；同一牌堆只使用一个实体、一个 AnimState，不新增逐纸实体或逐帧拼图任务。

## 5. 闪烁／整帧变黑：暂缓排查记录

### 用户观察与已做对照

1. 起初不确定是否整块显示器闪烁，改为窗口模式后认为主要在游戏内。
2. 控制台输入／自动暂停状态仍约每分钟闪一次；场景、物品栏、小地图受影响。起初觉得控制台文字稳定，但不确定；随后用户通过录屏确认整个游戏画面会短暂变黑。
3. 关闭NVIDIA游戏内覆盖仍复现；关闭多线程渲染并完全重启后仍复现，日志已确认 `Threaded Renderer: DISABLED`。
4. 切到不启用本 Mod 的存档仍复现。之后重启电脑、验证Steam完整性仍复现，主菜单也会闪。
5. 用户执行了禁用全部客户端模组并重启的对照，并测试另一款游戏《缺氧》：缺氧正常，饥荒仍闪。
6. **最终用户明确决定先不关注此问题，继续 Mod 开发。**

### 当时采集的证据（不是永久机器状态）

- 17:41前后：客户端私有内存约3.57 GiB，数次采样未见持续增长；RTX 4070 Ti显存使用约3.2 GiB，余约8.5 GiB。整机提交内存约92–93%，存在压力，但未发现内存分配失败。
- 17:49重启后，18:25采样：显卡约44℃、显存约2.4／12 GiB、可用物理内存约14 GiB；仍有闪烁，因此先前内存压力不能单独解释问题。
- 查询的时间段及重启后没有显示驱动重置、WHEA硬件错误记录；没有找到与黑帧对应的Lua崩溃／内存分配失败日志。没有错误记录本身不代表硬件绝对正常。
- 系统16:13集中上报的48条 LiveKernelEvent引用了历史转储，最新引用日期是11月6日；不能把上报时间当作本次故障发生时间。
- 曾有Windows录屏服务超时记录，尚无证据证明因果关系。
- 游戏日志中的 `Invalid resource handle for atlas 'FROMNUM'` 警告尚未定位来源，不能仅凭此警告认定整帧闪烁来自本 Mod。
- 0.25.14→0.25.15：全部打包KTEX文件字节约124 MiB→105 MiB；新卡堆没有因198张整图而膨胀。这个数值是纹理文件数据量，不是实际显存占用。
- 对比发现版本包同时包含音频与统计变更：音频库没有变大，FEV改动主要对应单音重复次数修正；统计代码由服务器事件触发，损伤桶和排行榜有数量上限，未发现暂停时按分钟无限增长的循环。此为代码审查结论，不是绝对排除所有缺陷。

**当前结论：本 Mod 直接导致闪烁的可能性已降低；优先怀疑饥荒自身或与驱动、配置等环境的兼容问题。根因未确认，未修复，也没有证明显卡硬件损坏。** 不应因本记录盲目回滚卡堆、音频或玩家统计。

## 6. 更早阶段仍需保留的用户约定

投射物和场地的详细实现、素材目录、编译错误与修复已持续记入第17号文档。该文档按时间追加，后段修订覆盖早段参数；用户随后明确表示法术效果与子弹基本没有问题，转入卡面制作。不要把早期设计草案重新当作待实现任务。

- 尾迹宽度要匹配弹头，巨化同时考虑视觉宽度与留存；魔法箭、燧晶投枪使用短段连续拼接，沿实际路径留下不同年龄的段，散弹要同时看到不同年龄的尾迹，不能等前段消失才生成下一段。
- 环绕半径按弹体特点适配是通用设计，不应只给魔法箭使用。虫弹朝左不能上下颠倒；蜂群、萤虫和环形场地的成员各自动作，避免整张纸片随镜头转动。
- 终点聚爆束保留原版紫色激光，沿轨迹留下可周期伤害的光带；限制最长留存时间，过期后从后向前逐段收细消散。用户接受碰撞修饰只在终点聚爆触发，中段周期伤害不反复触发该修饰。
- 月石、雷云、聚怪涡、电击环、幻鹿不再用额外范围圈表达大小；视觉应匹配实际范围，月石使用阴影与一次落地声。场地错贴图曾由动画图集超过着色器采样页上限引起，后续资源检查必须保留此约束。
