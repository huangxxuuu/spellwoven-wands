# 子智能体分工与成本控制

本项目的角色配置位于 `.codex/agents/`，默认值位于 `.codex/config.toml`；分类依据与使用说明见 [.codex/README.md](../../.codex/README.md)。

| 角色 | 任务 | 模型 | 推理强度 |
| --- | --- | --- | --- |
| `scout` | 只读检索、资源/日志清点、原版入口定位 | `gpt-6-luna` | `low` |
| `writer` | 文案、翻译、交接与已确认更新说明 | `gpt-6-luna` | `medium` |
| `worker` | 常规代码、UI、音源与资源构建 | `gpt-6.1-sol` | `medium` |
| `art` | 画风分析、Prompt、视觉设计与验收 | `gpt-6.1-sol` | `medium` |
| `verifier` | 定向验证、安装一致性、发布核验 | `gpt-6.1-sol` | `medium` |
| `specialist` | 复杂机制、联机/存档、性能和疑难排错 | `gpt-6-astra` | `high` |

1. 仅在任务能独立分工并节省主线工作时委派；简单任务直接完成，不为使用角色而创建子任务。未指定角色的子任务兜底为 `gpt-6.1-sol / medium`，不得惯性继承主会话的 `ultra`。
2. 优先选择上述自定义角色。若当前工具只有 `collaboration.spawn_agent`、没有角色选择参数，必须按表显式传入 `model`、`reasoning_effort` 和 `fork_turns="none"`，在任务消息中要求读取相应 `.codex/agents/<角色>.toml` 与 `AGENTS.md`。`task_name` 只是任务名，不能代替模型配置。
3. 默认传递目标、相关文件、用户已确认约束、允许修改范围、验收条件和已有证据，不复制完整对话。美术任务必须带上本次类别及[美术任务流程](../art/00_美术任务流程.md)要求的必读规范路径；发布任务必须交代说明是否已获确认。
4. 通常最多同时运行 2 个子任务。同一文件不并行写入，不让多个角色重复做同一轮检索/审查；子代理不自行再委派。
5. 需要跨模块因果推理、联机/存档边界或复杂性能诊断时使用 `specialist`；例行测试和文件检查仍使用 `verifier`。升级先移交已有证据，避免从头重查。
6. 默认不使用 `xhigh`、`max`、`ultra`；用户明确指定时按本次要求执行。主会话的模型和强度继续由用户选择，子角色不随之自动提高。
