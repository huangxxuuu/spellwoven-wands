# 版本发布前必读

1. 每次整理版本、准备发布、GitHub 同步或资料站发布前，实际读取 [发布流程](../发布流程.txt)，以该文件和 `tools/release.py` 为统一入口。
2. 先对比最近成功正式发布的冻结包，整理完整改动至 `docs/未发布改动.txt`，交由用户人工决定对外展示条目。确认前允许整理与验证，不提升版本、不准备正式快照、不提交发布 commit、不上传。
3. 用户已明确给出本次更新说明并要求发布，视为已确认，不重复询问；未明确时必须等待确认。不得自行选择对外条目后直接发布。
4. 确认后分别保存 `docs/releases/X.Y.Z-public.txt`（中英文精简对外记录）与 `X.Y.Z-commit.txt`（完整改动和验证记录）。同步 README、资料站记录及翻译，然后按 `prepare → commit → publish` 执行；完整记录进入 Git，Mod 版本与发布内容进入同一个 commit。
5. `--notes-approved` 仅能在本次对外说明已获用户确认后使用。它记录确认，不代替确认。恢复发布沿用已冻结的确认，不擅自增加对外内容。
6. 日常代码发布只更新 Mod 内容、更新记录、版本标签、GitHub 和资料站。不更新工坊封面、标题、描述或可见性；相关修改须有用户明确要求，使用独立工具执行。
7. 使用独立发布 checkout 和正式脚本的哈希、验证、断点恢复机制，不批量提交开发目录的无关文件，不手工伪造成功状态。脚本维护任务只做离线测试，不自动发布测试版本。
