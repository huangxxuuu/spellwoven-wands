## 常量入口

静态参数集中在 `mod/scripts/nw/constants/`。卡牌定义由 `card_parameters` 深复制后组装；`definitions.order` 仍由原注册流程决定，不能按参数表的遍历顺序重建。

| 类型 | 参数文件（均位于 constants） |
| --- | --- |
| 卡牌基础参数 | `projectiles.lua`、`fields.lua`、`modifiers.lua`、`multicast.lua`、`melee.lua`、`instant.lua`、`audio.lua` 的 `cards` |
| 修饰叠加与命中效果 | `modifiers.lua` 的 `rules/effects`、`projectiles.lua` 的 `effects`、`combat.lua` |
| 弹体、场地及实体生命周期 | `projectile_runtime.lua`、`field_runtime.lua`、`prefabs.lua`；哨株、活力环、和鸣见 `prefabs.garden` |
| 运动、施法与边界 | `motion.lua`、`casting.lua`、`world_bounds.lua` |
| 上下限、平衡与性能 | `limits.lua`、`balance.lua`、`performance.lua` |
| 原版效果适配与暗雾 | `native.lua`、`native_effects.lua`、`dark_fog.lua`、`fog_boss.lua` |
| 法杖、获取与收纳 | `wands.lua`、`acquisition.lua`、`storage.lua` |
| 外观与界面 | `visuals/`、`ui.lua`、`ui_misc.lua`；实体自身的外观默认值也见 `prefabs.lua` |
| 说明展示与原版参数兜底 | `description.lua`；[说明模板](../mod/scripts/nw/spell_parameter_text.lua)引用各类常量，[参数同步测试](../tests/test_spell_parameter_text.lua)验证中英说明随参数变化 |
| 日志、协议与训练设施 | `journal.lua`、`protocol.lua`、`training.lua` |

常量模块只返回静态数据，不加载游戏实体、世界状态、卡牌定义或执行模块。运行时会修改的表需复制；世界设置当前值、剩余寿命、计数器等继续留在运行模块。原版 `TUNING`、原版组件参数仍在运行时读取。数组索引、公式结构、协议编码以及开发测试场景输入不机械抽取；自动生成的图集和音频采样表由原生成器维护。

`modinfo.lua` 的宿主沙箱没有 `require`、`modimport` 或 `MODROOT`，配置菜单声明继续留在原入口；修改相关设置档位时需同时核对该菜单。独立预览工具会打包常量目录和 `util`，并监听常量文件变化，保持脱离主 Mod 安装时也能加载。

调整参数时同时检查说明模板的引用；中文与英文模板均应从同一数据来源格式化。不要在说明文字或兜底逻辑重新抄写已经抽出的数值。常量迁移不改变默认玩法，修改具体平衡值另行验证。

## 最小工作流程

1. 状态只在需要时查：`.venv/Scripts/python.exe tools/context.py --scope mod/scripts/nw/crafting_filter.lua tests/test_crafting_filter.lua --limit 10`。摘要包含未跟踪文件；省略路径有明确计数，扩大 scope/limit 可继续查。
2. 在命中的目录或文件检索，例如 `rg -n "关键词" mod/scripts/nw/crafting_filter.lua tests/test_crafting_filter.lua`；先定位再读取相关函数。不要默认打印全库 `rg --files` 或完整 Git 状态。
3. Lua 定向执行：`.venv/Scripts/python.exe tools/run_tests.py tests/test_crafting_filter.lua`；可传多个精确文件，`--list` 仅列选择。实际执行仍检查全部 Mod Lua 语法，每个测试使用独立 Lua 5.1 runtime；无参数保持全套回归。
4. Python 定向执行：`.venv/Scripts/python.exe tools/run_python_tests.py -p test_craftingfilters_widget.py`；可重复 `-p` 选择多组。其他离线检查使用 `.venv/Scripts/python.exe tools/quiet_check.py tools/check_localization.py`。默认仅输出末尾总结和失败摘要，完整日志按需查，`--verbose` 才回显全部。需要完整验收时按[验证与安装](验证与安装.md)执行。
5. 改动模块入口、已确认约束或验证方式时更新本表及对应专题；不复制大段机制/数值到导航。专题保留事实日期与实机验证边界。

## 检索边界

`.rgignore` 默认略过素材、输出、历史/研究文档、预览和正式发布记录，减少普通代码搜索的重复命中；文件仍保留，Git/构建/导出不受影响。资源任务先读资源索引，历史任务先查文档索引，再用 `rg --no-ignore -n "关键词" assets_src/具体目录` 或 `rg --no-ignore -n "关键词" docs/历史/具体文件.md`。直接打开已知文件不受这些搜索默认值限制。

这里列的是定位和起步测试，不能替代按改动风险追加联机、存档及客户端验证。复用主代理已交接的入口和排查证据，不重复整轮搜索。
