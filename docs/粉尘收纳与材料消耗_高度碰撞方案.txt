2. 材料销毁／无限消耗提案（未实现）

2.1 现状与目标
现有回收炉把卡和法杖变成粉尘；粉尘用于制作、空白卡和破损法杖修复。
精良杖消耗 24 粉尘＋1 巨兽核心，稀有杖消耗 40 粉尘＋1 霸主核心；
回收分别只返 8／12 粉尘。核心主要用于制作，成长完成后会积压。
“核心→粉尘”只是换一种积压形态，必须同时有无产物终点或长期消耗用途。
随机刷杖虽然可以反复消耗，却依赖玩家还想换杖，不能作为唯一清理渠道。

2.2 推荐先做：分解炉新增“还魔”动作
设定：解除晶粉与核心的束缚，让其中的魔力重新散入永恒领域。
入口：手持粉尘／任一种核心，对奥术分解炉使用“还魔（数量）”。
默认一次处理当前手持堆，动作约 1.5 秒，完成时消耗，走开则不消耗。
粉尘通常一次最多 40、核心通常最多 10，具体服从当前真实手持堆。
结果：一阵紫色光屑，零材料产出，零属性提升；可以一直重复。
若处于回收操作中，先结束回收再执行还魔，操作归属由服务端校验。
服务端检查物品所有者、炉子距离、实际数量与状态；完成那一刻只结算一次。

关键边界：
  不把粉尘、核心加入现有“附近地面物品自动回收”列表。
  不读取附近收纳盒、不追溯背包中的同类材料、不在动作中自动补下一堆。
  悬停就能看到要消耗的数量；动作期间物品移动或数量变化则取消，重新操作。
  先从真实堆叠取出对应数量，再播放成功效果；失败不生成假成功反馈。
这提供明确的销毁终点，开发范围最小，也不会改变战斗、掉落与成长曲线。

2.3 历史初稿：奥术余烬灯（已由 1.4 当前实现替代）
设定：将封存的魔力缓慢释放为柔和的照明。
可用新灯具；也可后续作为奥术台装饰功能，不改变原有制作能力。
建议先做固定地面灯，耗材只换照明，避免顺便替代回蓝、SAN、温度或伤害系统。

初稿数值（待试玩，不是已上线参数）：
  1 奥术粉尘：60 秒灯火，即 1/8 游戏日。
  1 巨兽核心：480 秒，即 1 游戏日，等效 8 粉尘。
  1 霸主核心：1,440 秒，即 3 游戏日，等效 24 粉尘。
  满储量：4 游戏日；开灯才消耗，可熄灭；照明半径建议 4 单位。
  配方建议：石砖 ×2、金块 ×2、紫宝石 ×1、粉尘 ×4，炼金引擎科技。

无限消耗指可以反复补充、持续燃烧；不是把任意多材料瞬间塞进有限油箱。
每次只接收能完整容纳的燃料单位，空间不足就拒收，不吞掉核心多余时长。
不根据燃料等级增强灯光；燃料表仅存持续时间，以后能新增燃料与纯装饰颜色。
服务器开着时按游戏时间消耗，休眠区补算经过的游戏时间；关服不计时。
存档保存剩余时长、开关状态、最后结算游戏时间；移除灯具不返还已投入燃料。
无可回收中间产物，不存在“烧核心→产粉尘→再制核心”的循环收益。

比较：
  还魔：直接清空积压，最快落地；没有玩法收益。
  余烬灯：稳定而温和的日常消耗；对已有灯源的后期玩家吸引力有限。
  法杖洗练：能大量消耗核心，但要重定稀有度与属性上限，不建议混在这一轮。
  粉尘补蓝：会改写法力回复及 SAN 换蓝的价值，暂不推荐。
  核心研碎：可作便利配方，但必须搭配前两者，不算独立销毁方案。

建议顺序：先上还魔作为通用清理入口；若希望材料长期“有用”，再追加余烬灯。
当前已启用 1.4 的粉尘燃烧；还魔、核心燃料与其他消耗渠道仍未启用。

3. 高度数据与碰撞提案（未实现）

3.1 推荐：数值区间驱动规则，定性词语负责展示
单个高度值不能同时表达物体的位置与厚度；只有“低／中／高”则难处理掠过墙顶、
变大弹体、矮小目标、抛物线、飞行升降及以后新增的物体。
建议用“所在高度＋占据的高度区间”，界面再显示贴地／低空／高空。
单位用游戏世界单位，不宣称现实米数；不要把屏幕像素直接当成碰撞高度。

各类数据：
  目标：bottom、top，表示相对所在支撑面的实体碰撞区间。
  飞行物：中心 height、垂直半厚 half_height，区间为 [height-half_height, height+half_height]。
  水平体积：独立 radius，与垂直厚度分开；不强迫所有对象为球。
  轨迹：height_at(t)，直射可线性，抛射为原版 complexprojectile 的真实 Y。
  可视信息：visual_lift / 渲染偏移单独保存，光晕、拖尾、卡面边框不扩大命中体积。
  分类：grounded / airborne / column 等用于选择算法，不取代底层数值。

示例调参起点，必须以游戏内可视化校准，不能宣称是原版精确身高：
  蜘蛛：目标 [0, 0.7]。
  普通角色：目标 [0, 1.8]；骑乘状态由坐骑适配器给出新体积。
  常规墙：目标 [0, 1.6]；实际区间随墙的形态／高度阶段解析，破墙不挡弹。
  飞行小生物：中心 1.8、半厚 0.3，即 [1.5, 2.1]；不是从地面到 2.1 的实柱。
  普通小魔弹：半厚 0.12，中心沿弹道变化。
  落地晶体／载荷卵：接地底部 0，高度各自配置。
  星体：单独记录悬浮中心与体积，不从光照圆或发光像素反推。

面向玩家的粗略标签可由中心高度派生：
  贴地：中心 <0.4；低空：0.4 至 <2.0；高空：≥2.0。
  这些阈值只用来描述弹道，不参与伤害判定，也不代表某种生物只能挨某类法术。
  调试面板／资料站详细数据可显示准确区间；普通卡面展示词语与必要的特殊规则。

3.2 本项目已有机制与接入点
nw/muzzle.lua 从手部位置读取出膛高度，兜底为 1.2，骑乘另处理。
nw/flight.lua 将多数弹体物理实体保持在地面；图像通过独立高度偏移悬浮。
nw/projectiles.lua 共用服务端更新器，按上一帧到本帧的实际 XZ 路径扫掠。
nw/geometry.lua 目前返回射线进入水平圆的最早时刻，没有区间终点。
nw/electric_visual.lua 的 tiny/small/med/large 和 low/high 目前仅是视觉定位估计。
星体移动已用 ignore_walls 做越墙特例；晶体／卵有独立海岸与船面边界规则。
持久光束保存的是水平线段，载荷与移动场也已有保存数据。
所以不能把 Transform.y 当成所有法术的唯一高度，也不能简单给 Geometry.hit 后面加一次高度比较。

3.3 注册与解析架构
建议新增独立模块 nw/collision_profiles.lua、nw/collision_height.lua，保持原版实体与其他 Mod 的攻击不变。
profile 示例：
  spider = {bottom=0, top=.7, radius_mode="native", grounded=true}
  small_flyer = {center=1.8, half_height=.3, radius_mode="native", grounded=false}
  spark = {half_height=.12, height_mode="trajectory", scale_mode="center"}

解析优先级：显式实体覆盖／动态适配器 → prefab 注册 → 标签兜底 → 保守兼容兜底。
提供 register_prefab、register_tag、register_resolver 三个登记入口，未知对象无需改主循环。
普通实体静态数据可缓存；飞行、骑乘、下潜、死亡、墙体形态等动态状态按帧解析并缓存到本帧。
多 Mod 同优先级注册有确定顺序与一次性日志，不静默依赖遍历顺序。
参数必须有限且 top>=bottom；缺失或非法配置回退兼容行为，并按 prefab 只记一次开发日志。
未知模组生物先沿用旧水平命中行为，避免上线后变成无法命中的对象；调试工具列出未覆盖项。
兜底规则不是对已登记低空生物无限延高，只在缺失数据时使用。

3.4 高度碰撞算法
第一步继续复用当前空间查询与目标筛选，不逐弹扫描全世界。
第二步求弹体扫掠与目标水平扩张圆的重合时间段 [t_enter, t_exit]。
第三步在同一时间段内求垂直区间相交的时间段，两者相交才构成碰撞。
返回真正首次三维接触时刻 t_hit，再与其他目标、墙、定时触发按时间排序。
端点相切算命中，统一给很小的 epsilon（初稿 0.02），不能不同分支各用一个容差。

不能只在平面入射点测一次高度：抛物线进入目标平面投影时可能仍在头顶，
随后才下降碰到身体；应在水平重合时间段内继续找垂直交点。
直线采用区间解析求交；原版抛物线使用分段运动采样，必要时按曲率细分，
保证每段高度近似误差在约 0.02 内；最高点也应成为分段点。
对移动／升降目标记录前后体积，以相对运动求交；瞬移需分段重置，不扫过整条传送路径。
高速弹、低帧率下也走扫掠；不能只检查当前落点，避免穿过薄墙或小目标。

3.5 瞄准必须与高度一起设计
现状多数直射弹从约 1.2 的高度水平前进，若直接加真实高度会飞过蜘蛛。
建议目标选择模式：保持现有 XZ 瞄准点，对准目标体积内的一个高度，建立直线竖向斜率；
瞄准点优先选择离出膛高度最近、并留有边缘余量的有效高度，避免不必要地俯射地面。
鼠标方向模式：保留用户指定的水平射线，只在该射线上寻找首个合法目标作竖向辅助，
不得向射线外目标侧向吸附；无目标保持当前高度。
辅助目标仍受队伍、选择卡、遮挡与射程限制，不能让弹体为命中目标而穿墙。
此竖向辅助属于明确的体验变更，建议在测试版单独开关验证后才随高度碰撞一起开启。
追踪只按统一目标体积选点；未来竖向追踪以单独转向／加速度上限实现，不能瞬间改高。
出生点检查也用同一碰撞规则，避免先把弹体生成到薄墙另一侧。

3.6 碰撞体与效果范围的区别
普通直射：有实体命中高度，只命中相交目标。
墙：完整墙体按区间阻挡；从墙顶上掠过不扣穿透、不反弹、不释放碰撞载荷。
穿墙修饰：仅跳过墙的阻挡／命中逻辑，不自动跳过生物、树或建筑。
地面机关：接地判定与触发范围分开；感应雷可以感应飞行生物，是否可感应由其配置规定。
范围爆炸：配置为球／圆柱等效果体积，不能继承小弹丸的 0.12 半厚。
地面火环／地刺：有限高度的地面效果；雷击：纵向柱；治疗／光照光环按原有效果语义定义。
连锁闪电：独立“是否需要视线”与每跳距离策略；不能因为视觉电弧很高就漏掉目标。
持续光束：每条历史段保存起终高度和厚度，接触检查沿整段，不仅看移动头部。
护盾／环绕：同样消费统一高度体积，否则弹体会被视觉上相隔很远的护盾拦下。
攻击资格、伤害免疫与碰撞阻挡分开：飞行高度相交，不代表能伤害处于原版无敌状态的目标。

3.7 巨化、载荷、地形与保存
巨化：同时缩放水平半径与垂直半厚，默认围绕弹心；接地实体底部固定在地面向上长。
光效的屏幕缩放不算两遍；已有星体与原版弹体的缩放适配应复用同一倍率。
碰撞载荷：从真实接触位置和高度生成；定时载荷从触发时刻的插值位置和高度生成。
生成贴地机关的载荷按“落地／投放”策略放到支撑面，不能把所有子法术强行悬空。
原版复杂抛射物读取真实 Y，直射弹使用逻辑高度；二者互斥，不能重复加高度。
海面、船、码头及地图外边界维持独立规则；高空越过矮墙不意味着贴地机关可以越海。
永久实体保存 schema 版本、逻辑高度、竖向速度、轮廓 ID、必要动态状态。
旧存档由 ID 与旧 height 恢复兼容默认值，不强制重抽属性，也不改写法术卡实例 ID。
只同步客户端需要的视觉高度／轨迹参数；服务端决定命中，不为所有原版生物增加网络变量。

3.8 分阶段落地与验收
A：只补轮廓数据、解析器、调试碰撞轮廓与“缺失数据”报告，实际命中保持现状。
B：在隔离测试世界启用直射＋墙＋目标竖向瞄准，覆盖常见生物和原版状态。
C：接入抛射、穿透／反弹、碰撞／定时载荷、光束、护盾、地面机关、范围效果。
D：最后迁移星体越墙特例及永久实体存档，完成远程客户端检查后正式启用。

必要场景：
  矮生物在近处／远处均可正常命中；鼠标方向不侧吸目标。
  弹底略高于墙顶通过，擦边命中；破墙放行，换形态立即更新。
  空中目标下方可穿过贴地法术，下落过程中能与扫掠弹体相撞。
  抛物线平面重合期间下降命中；高速与低帧率不漏检。
  巨化擦墙、多个目标时序、穿透计数、反弹与载荷不重复结算。
  远程客户端轨迹与服务端命中一致；不额外扩大空间查询次数。
  地图边界清理、主人离线、存档重进、未知 Mod 生物均有兼容行为。

建议最终选择：数值区间作为真实碰撞数据，词语作为展示；先补数据与调试，
再把竖向瞄准和碰撞一起上线。不要先把现有 visual height 直接变成伤害门槛。
