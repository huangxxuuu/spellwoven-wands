## 2. 主分类

每张卡只有一个主类。主类回答「这张卡在施法组合中主要承担什么职责」，不按伤害元素、武器来源、稀有度或实用用途拆成更多边框类型。

| 主类 | 玩家理解 | 覆盖范围 | 边框 |
| --- | --- | --- | --- |
| 基础法术 | 产生一个实际效果或载体 | 飞行投射物、近战动作、瞬发效果、地面实体、场、音乐效果，以及自身能承载后续法术的载体 | 轻切角矩形 |
| 法术修饰 | 改变法术或法杖的表现与参数 | 伤害、速度、寿命、弹道、命中附效、目标选择、蓝耗和充能等修正 | 上下尖的竖向六边形 |
| 施法控制 | 改变法术怎样组织和释放 | 多重抽取、释放方向组织、输出复制，以及给下一载体附加释放载荷机制的独立控制卡 | 顶部中央宽凹口矩形 |

三个主类对应「效果是什么」「效果怎样变化」「效果怎样组织释放」。不新增「治疗」「采集」「音乐」「火焰」等主类；这些概念适合做标签和筛选条件。

### 2.1 容易误分的边界

| 卡牌或情况 | 归类原则 |
| --- | --- |
| 普通火花弹、火焰弹、冰霜弹 | 基础法术；是否造成火伤或冰冻不改变边框 |
| 自带碰撞或定时载荷的弹体变体 | 仍是基础法术，用机制角标区分；不是改成施法控制边框 |
| 延迟符印 `delay_seal`、空心载荷卵 `payload_egg` | 自身产生载体，归基础法术；分别使用定时载荷和被击破载荷标识 |
| 独立的 `imprint_hit`、`imprint_timer` | 归施法控制；其主图直接表达碰撞或定时控制，不再重复加同义角标 |
| 双重、三重等多重施法 | 归施法控制；主图表达分叉或多路释放 |
| `repeat_2`、`repeat_3`、`repeat_4` 等复制输出 | 归施法控制；不能仅因内部实现是修饰字段而放进修饰主类 |
| `mana_reduce`、`recharge_down`、`wild_charge` | 归法术修饰；影响费用或充能仍是参数修正 |
| 命中爆炸 `explosion`、击退、汲取等附加效果 | 归法术修饰；发生在命中时不等于「释放后续载荷」 |
| 目标选择 | 归法术修饰；通过标签或说明写明影响对象 |
| 武器刻印 | 按实际作用归类；发射武器、进行近战或产生实体通常为基础法术，不按「刻印」单列主类 |
| 陶笛、弦琴、音符 | 按实际机制归类，并加音乐用途标签；不因音符外观产生第四种边框 |

判断优先看实际行为，不能只看卡名或现有 `kind`。现有运行时的 `projectile`、`field`、`melee`、`instant`、`note`、`modifier`、`multicast` 等内部类型可以继续服务施法逻辑，玩家主类应独立建模。

### 2.2 分类数据的后续组织

建议为每张公开卡明确维护玩家主类、标签、作用范围和角标类型，统一提供给收藏册、筛选、悬停面板和美术构建。以下仅为字段职责示例，不是已经落地的接口：

- `primary_class`：唯一主类，决定边框轮廓。
- `tags`：多个稳定的机制与用途标签。
- `scope`：作用范围和依赖说明。
- `mechanism_badge`：无、碰撞载荷、定时载荷或被击破载荷。

新增卡必须显式审核这些信息。禁止用「找不到分类就统一当基础法术」掩盖遗漏；内部类型变化也不能自动改变玩家边框。

## 3. 标签与信息面板

### 3.1 标签的用途

标签帮助玩家在同一主类中区分具体行为，并允许跨主类查找用途。例如基础治疗弹与治疗修饰都可以通过「治疗」找到，但保留各自不同的边框。

| 标签维度 | 例子 | 主要回答的问题 |
| --- | --- | --- |
| 作用形态 | 投射物、近战、瞬发、地面实体、范围场 | 实际会产生什么形态的效果 |
| 修正方向 | 弹道、速度、伤害、寿命、目标、费用、充能 | 修改哪一部分行为 |
| 释放机制 | 碰撞载荷、定时载荷、被击破载荷、多重抽取、输出复制 | 组合或释放有什么关键规则 |
| 实用用途 | 治疗、防御、采集、音乐、照明 | 玩家可以拿它完成什么任务 |

上述是标签词表的组织方式；不是要求一张卡必须从每个维度各选一个。主类唯一，形态、机制和用途标签可以多值。一个概念只保留一个统一名称，避免「碰触」「碰撞」「命中载荷」在不同界面中混用而造成理解成本。

标签描述卡牌自身的稳定属性。临时受到其他卡修饰后的结果，不应写回卡牌基础标签。不要把每个伤害值、速度值、百分比或秒数转成标签；这些属于参数。标签不能替代作用范围、数值、前置条件和例外条款。

### 3.2 在哪里显示

- **物品栏卡面**：只显示边框、纸底、主图、必要的机制角标；不把标签文字堆在小图中。
- **悬停信息面板**：显示主类及最重要的 2–3 个标签，再给出一句直白作用说明。
- **收藏册详情**：可以显示完整标签、参数、范围、机制说明和关联变体；展示区与规则文字区分开。
- **收藏册与制卡筛选**：主类负责一级筛选，标签支持组合筛选；用途标签可跨主类检索。
- **地面卡牌与卡堆**：不绘制标签列表；通过顶牌、轮廓、主图和必要的角标识别。

标签按「决定使用方式的机制优先、作用形态其次、用途补充」选择展示，不追求每张卡都凑满三个。

### 3.3 信息面板顺序

建议顺序为：卡名 → 主类与重点标签 → 一句话作用 → 作用范围或依赖 → 核心参数 → 展开的详细规则。短面板优先帮助玩家决定「放在这里是否有效」，完整参数放进详情层。

必须明确写出真实作用范围，例如：

- 「本施法组」：改变当前组内的对应效果。
- 「下一载体」：只给下一张适用的载体附加机制。
- 「后续法术作为载荷」：后面的法术预装进当前载体，等待指定事件释放。
- 「本轮法杖充能」或其他准确范围：用于并非只作用于当前弹体的参数修饰。

这些表述按真实实现选择，不能把所有修饰都笼统称为「作用于下一张卡」。对静止实体、特定武器、载荷或目标限制的例外，保留在详细规则中。

展示结构示例，不替代正式数值说明：

> 火花弹·碰撞  
> 基础法术 · 投射物 · 碰撞载荷  
> 发射火花弹，发生有效碰撞时释放预装法术。  
> 组合关系：后续法术作为载荷。具体补发、墙体与重复触发规则见详情。

## 4. 牌面构成

### 4.1 图层职责

从下到上依次为：纸底 → 主图 → 边框 → 机制角标。边框与纸底可由同一母版导出，但源文件应能独立编辑；原生堆叠数量由游戏界面叠加，不烘焙进贴图。

当前深化保留 A 的框宽、双线结构和饱满层次，继续保持三种主类轮廓，不将边框压成单薄的平面单线。内侧卷角及其翻折阴影不恢复；本轮可以调整边框色带、高光、纸纹和磨损，使纸卡更精制、完整并蕴含魔力。

手绘感通过略有变化的线条和有控制的笔触保留，不能主要依靠明显裂纹、破口、污斑或密集排线表达。边缘应干净完整，中央主图区保持安静。

外轮廓之外为真实透明区域；纸底保持不透明。不能依靠物品栏格子的背景充当卡纸，否则收藏册、地面和不同界面背景下会失去一致性。

收藏册和物品栏保持正面展示。地面版让纸底、主图、边框与角标共同接受透视，不能只有边框变形而主图仍朝向屏幕。

### 4.2 三种轮廓的几何起点

以 64×64 透明画布为基准，卡牌包围盒为 `x=6…58、y=4…60`，宽 52、高 56；描边约 2.5 像素。以下顶点使用卡牌包围盒内的局部坐标。

| 主类 | 轮廓参数 | 最重要的识别特征 |
| --- | --- | --- |
| 基础法术 | 52×56 矩形，四角各切约 4 像素 | 连续平顶、两侧竖直、四角轻切 |
| 法术修饰 | `(26,0) (52,12) (52,44) (26,56) (0,44) (0,12)` | 上下尖、左右保留足够长的竖直段 |
| 施法控制 | 使用基础矩形外廓，在顶部 `x=18…34` 开宽 16、深 8 的中央凹口 | 清楚的中央凹口，避免做成细小缺损 |

可增加少量手绘不规则，但不能磨平尖顶、填掉凹口或把切角矩形改成普通圆角牌。收藏册版也必须保留这三个轮廓，不在外面再包一层相同大矩形遮掉分类差异。

这些形状是本 Mod 的交互约定，不赋予未经定义的饥荒阵营、月亮、暗影或稀有度含义。玩家通过主类名称与一致使用学习规则。

### 4.3 统一浅暖灰纸底

| 位置 | 起始色值 |
| --- | --- |
| 顶部 | `#E5DCC9` |
| 约 55% 高度 | `#DDD3BE` |
| 底部 | `#D4C7AD` |

使用极轻的自上向下线性渐变；不采用中心发亮的径向渐变，不按主类铺三种不同底色。纸底为主图提供稳定的明暗对比，边框负责主类辨识。

本轮边框采用以下起始试色。它们是供生成和比较使用的颜色，不是最终实机定稿；需要放入真实主图，并经过小图和游戏纹理检查后再决定。

| 部位 | 本轮起始试色 | 用法 |
| --- | --- | --- |
| 外轮廓 | `#2B2929` | 接近黑色的清楚轮廓，保留手绘笔触 |
| 边框色带 | 墨褐 `#51463F` | 承接双线结构与饱满层次，避免整圈过亮抢主图 |
| 窄高光 | 灰金 `#AD9A7D` | 少量、窄幅地提亮边框，不铺成大面积金属金边 |

收藏册版可以有细微纤维和低对比纸纹；减少明显受损、古旧污痕与密集排线，保持完整边缘。物品栏版进一步归并细纹理，保留干净的浅色区域；地面版保留纸边与体积信息。纸纹不能形成类似法术图案的高对比噪声。

### 4.4 主图

主图用一个清楚的主体轮廓表达法术作用，以大形、明暗层次和有限的亮核或晶面强化能量感。把细碎纹理归并成大的明暗块；饱满来自清楚的体积和能量中心，不靠不断增加碎线与装饰。

- 有明确原版武器或道具对应关系的法术卡，原则上直接使用该原版武器或道具的素材；这条优先于按实际弹丸重绘主图。例如原版法杖刻印用对应法杖，不能仅因施法时产生魔弹就改成通用魔弹图。用户另行明确的三个近战动作例外见下文。
- 旋斧攻击 `whirl`、长矛戳击 `thrust`、玻璃刀砍 `slash` 单独绘制主图，分别用原版斧头、长矛、玻璃刀的可辨形象配合旋转、前刺、挥砍轨迹表达动作；不归入仅缩放原图的卡。主体和动作轨迹都应完整位于卡框内缘以内。
- 没有上述原版道具对应关系的投射物，使用实际弹丸或载体形象，普通版与机制变体共用同一主体。
- 修饰使用明确的方向、轨迹或效果变化；控制卡使用清楚的分叉、重复或多路结构，避免把完整战斗场景塞进卡面。
- 多重施法、复制等控制卡的必要倍数可成为主图的一部分。
- 音名、倍数等确有必要的信息属于该卡主图设计，不占用通用机制角标位置。
- 主要轮廓应在 64 像素下清楚，32 像素下仍可识别大致用途。复杂机制由信息面板解释。

同一系列的普通、碰撞、定时变体保持主图大小和位置一致，预留右下角标空间。无角标的普通卡不保留空白徽章底座，也不因此额外放大主图。

#### 原版武器与道具的直接复用规则（2026-11-07 确认）

1. 通用规则适用于有明确原版物品来源的法术卡，不只工具刻印，也不按 `edge_` 前缀限定；**明确排除用户指定单独绘制的 `whirl`、`thrust`、`slash` 三个近战动作卡**。依据 `source_weapon`、原版物品映射、显式例外及实际机制核对；外观相似不足以认定对应关系。火焰弹等自定义能量弹不能因为颜色相近就替换为原版火魔杖。
2. 从原版物品图标或原版动画贴图中选择完整、清楚的武器/道具主体，保存原版来源与帧信息；不交给生成模型重新描绘，也不额外补纹理、换色、描边、加宝石或泛光。原版低分辨率是素材本身的特性，不通过 AI 重画来伪造高清。
3. 只做透明外边距整理、等比缩放和定位，保留原始朝向、比例、颜色及完整轮廓。不得非等比拉伸、裁掉可见部件，或把主体伸出边框来追求尺寸。
4. 按实际边框的**内缘可用区域**计算适配范围，保留很小的安全间距；在完整轮廓位于该区域内、且不侵占必要角标关键空间的前提下，使用尽可能大的等比缩放比例。不能按整张方形画布尺寸直接放大，也不能因透明留白把主体压小。收藏册、物品栏、地面版分别按各自内缘计算。
5. 原版物品与普通、载荷变体的对应关系保持一致。普通版不额外放大，同系列变体复用已确定的主图位置与大小。

当前公开卡表中，63 张卡具有明确的 `source_weapon`，再加上明确产生原版道具的火药 `gunpowder`，合计 **64 张具有明确原版来源的卡**。其中 **61 张直接使用原版素材**（60 张 `edge_` 卡与火药），**3 张单独绘制动作主图**：长矛戳击 `thrust` 对应长矛、玻璃刀砍 `slash` 对应玻璃刀、旋斧攻击 `whirl` 对应斧头。数量是本轮核对快照，后续以公开卡表、显式来源映射与例外清单为准，不能用前缀或文件存在与否代替来源审核。这是设计分工，不能据此宣称全量运行时主图已迁移。

本规则已用于四主图样稿的工具选择：园艺锄改用原版 `quagmire_hoe` 的 `hoe01` 图形，先前生成的园艺锄仅保留为历史稿。旧卡面构建目前允许主图越过边框，正式迁移时必须一并改为内缘适配；文档确认和样稿替换不代表全部运行时资源已迁移。

### 4.5 主图的颜色与能量表达

保留现有主图的识别特征，并用下面四类作为后续组合检验的基准：

| 检验主图 | 保留的颜色与形象 | 深化方向 |
| --- | --- | --- |
| 火焰 | 橙红主体与清楚的亮核 | 用完整火焰大形和明暗层次集中能量，避免边缘碎成许多小火丝 |
| 冰霜 | 青蓝主体、白色晶面 | 通过少量明确晶面与明暗转折表达冷硬、清晰的能量，不铺满细裂纹 |
| 重弹 | 深色外壳、紫色亮核 | 用外壳与亮核的强弱对比表达重量和内部能量，保留饱满外形 |
| 对应原版的武器或道具（排除三个近战动作例外） | 直接复用原版主体、颜色、描边与材质 | 仅等比缩放和定位，在边框内尽量大，不重新绘制材质或添加能量装饰 |

三个近战动作例外保留对应原版武器的识别特征，单独绘制武器与清楚的动作轨迹；通过旋转、前刺、挥砍的不同构图区分法术。它们不改变园艺锄等其余原版道具的直接复用规则。

修饰和施法控制的魔力感主要来自清楚的轨迹、指向、重复和层次，武器实体主要来自扎实的形体与局部亮点。亮核或晶面用于适合的主体，不要求每张卡都有同样的发光中心。

不统一加大范围泛光，也不在所有卡底铺满魔法阵。收藏册可以有细致刻线和克制微光；物品栏应合并这些细节，保持大形与对比；地面版仍为平躺纸卡或纸堆，不能因为强调魔力而变成悬浮发光框。

边框打样可以先展示空框，但后续判断是否成立，必须放入火焰、冰霜、重弹、武器或工具四种主图，检查暖色、冷色、深色和实体主体是否都能与纸底、边框共存。不能仅凭空框的装饰效果确定最终版本。

## 5. 机制角标

### 5.1 使用条件

角标只用于「这张基础载体自身在什么事件下释放后续载荷」。它不是所有碰撞、爆炸、倒计时或特殊效果的通用标记。

| 角标语义 | 使用对象 | 图形方向 |
| --- | --- | --- |
| 碰撞载荷 | 自带碰撞释放载荷的弹体与载体 | 简单的碰撞接触符号；具体笔画待小尺寸试画后选择 |
| 定时载荷 | 自带定时释放载荷的弹体、延迟符印等 | 简单计时符号；具体采用钟面还是其他计时轮廓待选 |
| 被击破载荷 | 载荷卵等被攻击击破后释放载荷的实体 | 简单受击破裂符号；与碰撞标识保持可辨差异 |

碰撞与被击破必须区分：前者描述载体撞到目标或墙面，后者描述实体受到攻击后破裂。角标表达机制族，不承担触发次数、延迟秒数、补发条件等全部规则。

以下情况不添加同义角标：

- 独立的碰撞触发修饰与定时触发修饰：主图已经表达其控制职责。
- 普通晶雷、休眠晶体、火药或命中爆炸修饰：自身爆炸或带引线并不等于释放后续法术载荷。
- 普通治疗、防御、采集、照明等用途：由主图和标签表达。

现有角标按单一机制设计。将来出现多个同时存在的载荷释放条件时，应先重新评估表达规则，不直接叠加多个小徽章挤占卡面。

### 5.2 位置与叠层

原生物品堆叠数量在**顶部居中**，应保留这一区域的可读性。机制角标位于**右下角，轻压边框**，大部分仍在卡牌内部，少量跨过外轮廓。

以 64×64 画布为制作起点：角标占约 18×18，包围盒约为 `x=43…61、y=44…62`。相对卡牌右边界约伸出 3 像素、下边界约伸出 2 像素；整体仍在画布内。约七成以上面积留在卡牌区域，实际可按三种轮廓微调视觉位置。

角标使用浅色不透明底和深色单层轮廓，盖住其下方的卡框线条，防止两条线交叉。符号以少量粗线构成，不使用厚重投影、宝石高光或细密外圈。收藏册版可提升边缘精度，但不能换成另一套语义或把角标做成装饰主角。

## 6. 地面单卡与卡堆

### 6.1 平放叠高

所有卡牌平行于地面；俯视下远边较窄、近边较宽。整摞卡主要在高度上从下向上堆叠，前侧细薄纸边表现厚度，阴影贴在底部。

取消先前为了露出三种上缘而向后大幅错开的做法。底牌只做极轻的左右错位或角度变化，保持整齐的平放关系；不做竖立、扇开或阶梯式陈列。

### 6.2 内容与外观的关系

1. **顶牌真实**：按容器从左到右、从上到下的格子顺序，找到第一个非空位置作为顶牌；显示它的真实主类、主图和必要角标。
2. **底牌自然遮挡**：若制作下层形状变化，按真实顺序取后续卡牌，最多处理靠近表层的两张；仅自然露出其局部轮廓，不保证三种上缘或三张卡都能看清。
3. **不挑选代表牌**：前三张同类就呈现同类表层，不从深处抽取其他主类来营造「三类俱全」的外观。
4. **数量表现厚度**：2–3 张为薄堆、4–6 张为中堆、7–25 张为厚堆；厚度增长收敛，底部用统一纸边概括，不逐张画出 25 层。
5. **一张恢复单卡**：卡堆只剩一张时恢复独立卡牌；不保留空卡堆外壳。
6. **完整构成放信息面板**：可增加「基础 10 · 修饰 6 · 控制 2」等准确统计，不能把表层可见轮廓当成整堆构成。

例如表层顺序为「基础、基础、修饰、控制」，顶牌是第一张基础卡；控制卡暂时被遮住是正常情况。若六边形顶牌下方是矩形卡，矩形边角可以自然露出；不要为露出底牌额外增加大的后移量。

显示顺序不改变容器交互：玩家仍可任意取出格子中的卡牌。创建牌堆时也不自动改成「最后放入的卡总在最上面」。各层偏移和角度保持稳定，增减卡牌时更新内容与厚度，避免每次重新随机散开。

### 6.3 当前实现与需要补的部分

现有容器为 5×5、25 格，每格一张，`acceptsstacks=false`。卡堆张数为容器内物品数，与物品栏中同种卡的原生堆叠数量是两回事。

当前已按第一个非空格选择顶牌，并按 2–3、4–6、7–25 的阈值选择地面动画；剩余不超过一张时会释放剩余卡并移除容器。网络表面数据当前只包含总张数和顶牌代码，不能据此复原第二、第三张的主类。

现有构建已使用上窄下宽的地面透视及向上增加厚度，但底部纸边共用基准轮廓。真实下层类别轮廓、三主类统计和新美术资源需要后续实现，不能仅靠调整现有表面数值获得。

### 6.4 多形态底堆设计

顶牌复用实际单张卡面，仍区分切角矩形、六角形、顶部凹口矩形。内部卡牌只按两种轮廓处理：R 为矩形（内部凹口矩形也归 R），H 为六角形；不再为内部凹口另绘一类底堆。顶牌的顶部凹口矩形记为 N。

当前以顶牌加两张底牌制作对照，紧贴顶牌向下依次为 RR、HR、RH、HH 四种组合，分别覆盖没有六角形、一张六角形在上、一张六角形在下、两张六角形。与三种顶牌组装形成十二种外观。完整三字母组合按从顶到地面的顺序读取，例如 RHR 为矩形顶牌、六角夹层、矩形底牌。

**H 必须真实缺少相对 R 的角部空间。** 不能先画完整矩形侧墙，再外挂一个六角形前尖来代替 H；每层纸面与其厚度侧边都必须遵循该层真实轮廓，缺角处不能补成浅色矩形填充。

| 从顶到地面的组合 | 前缘与缺角处必须表现的关系 |
| --- | --- |
| RRR | 连续三层矩形纸边，作为没有夹层缩进的对照 |
| RHR | 上层 R 在缺角处形成悬边，下层 R 的纸面形成承托面；中间 H 向内退进，二者之间出现局部阴影凹槽。凹槽只占 H 这一层的高度，不能穿过下面真实存在的 R，变成贯穿整堆的洞 |
| RRH | 两层 R 的角部下方，最底 H 向内收窄；露出悬边和地面暗影。不能画出不存在的完整矩形底座来承托这些角 |
| RHH | 两张底牌的角部都向内收窄，按各自高度保留 H 轮廓；不能在任何一层恢复成矩形侧墙或底座 |
| NRR、NHR、NRH、NHH | 前缘分别沿用对应 R 顶牌组合的规则；N 的顶部凹口仍由下层真实纸面自然显露，不改变前缘缺角关系 |

底堆在**每张卡自身轮廓内**保留完整空白纸面，由顶牌自然遮挡，不预先挖掉统一顶面区域；六角顶牌下的矩形露角，以及凹口内露出的下层纸面，都由此保留。缺角形成的凹槽来自层间轮廓差异，所有有纸的接触区域仍紧贴对齐；不通过爆炸分层、悬空拉开间距或扇形展开来强调空位。

顶面随厚度向上移动，底部接地点保持稳定。更多卡牌的厚度另按既定三档处理；此处的六角形数量指当前画出的两张底牌，不等同整堆类别统计。

[卡堆多形态外观 v4](../assets_src/spell_card_frames/v4_pile_variants/README.md) 的旧图保留供追溯，但内层 H 的缺角与退进凹槽未正确表现，不能作为这些空位已精确绘制的依据。[卡堆缺角与夹层凹槽 v5](../assets_src/spell_card_frames/v5_pile_recess/README.md) 的四种放大对照与十二种组合修订图已于 2026-11-07 获用户确认，作为后续结构制作参考；正式资源仍按上述组合逐项验收，尚未切片和接入运行时。

## 7. 收藏册 物品栏与地面资源

三种用途共享轮廓、纸色、主要装饰语言和机制符号。它们是同一套卡牌的不同细节版本，不是三套互不相关的美术。

以下尺寸是本轮建议的制作起点，不是已确认的引擎限制，也不表示收藏册功能已经存在。

| 用途 | 建议母版或导出 | 制作重点 |
| --- | --- | --- |
| 收藏册单卡 | 2048×2048 母版，1024×1024 展示导出；按页面实际显示大小调整 | 轮廓清晰，纸纹与装饰经得起单张放大观看；中央保持足够大且安静的绘图区 |
| 物品栏 | 独立简化版，64×64 目标导出，另保留 128×128 版本 | 主要用粗轮廓和少量大装饰；在 64、32 像素和实际法术槽大小检查可读性 |
| 地面单卡与牌堆 | 建议从 256×256 工作画布起步，按构建边界与透视重新裁切 | 顶面透视、前侧纸边、贴地阴影；主图与角标共同变形，避免悬浮 |

当前库存确实使用 64×64 资源；现有地面构建工作画布为 230×172。引入新的 256×256 工作画布时，需要重新核对裁切、枢轴、地面接触点和动画尺寸，而不是直接覆盖旧文件。

### 7.1 收藏册精细版

保留 A 的框宽、双线结构、切角与饱满层次，采用本轮起始试色探索更精制的魔法卡纸。可以使用细致刻线、细微纸纹和克制微光；减少裂纹、破口、污斑和密集排线，不恢复内侧卷角。

放大后可以看到细节，缩略时首先看到三种主类轮廓。同一风格的三个主类要使用同一种材质和笔触；不能把主类画成不同等级的稀有度。

收藏册中的卡名、说明和标签可以由界面排版提供，边框母版不烘焙卡名、数值、稀有度或数量。边框应能复用于所有同主类卡。

### 7.2 物品栏简化版

后续正式制作仍需独立处理小尺寸可读性，不能把收藏册精细版直接缩小后当作最终资源。应检查凹口、尖顶和切角的区别，保留已选 A 的框宽与双线结构。细刻线、微光和纸纹在小图中应简化或归并成大明暗块。

后续资源验收需检查顶部数量、右下角标和主图空间是否清楚，主图与纸底应有足够对比。不通过缩小主图来容纳新增装饰。

### 7.3 地面版

地面版继承本轮卡纸配色与完整边缘，并保持适合小尺寸的细节密度。平躺地面、从下向上堆叠、前侧纸边与底部接触阴影的规则不变；微光不能盖住纸边、抹掉主类轮廓或造成悬浮感。

单卡、薄堆、中堆和厚堆共用稳定的底部接触位置。若不同主类自然露出底牌边角，仍保持各张卡平行地面，不绕角度把底牌竖起来帮助识别。

### 7.4 文件分层与命名建议

每种候选风格下分别保留三主类的收藏册、物品栏和地面资源，另保留纸底、框线、角标与预览图。建议命名包含 `style`、`primary_class`、`usage`、`size`，例如 `ink_basic_album_1024.png`。

正式接入前先保留未合成的透明边框层与不透明纸底层，再按用途输出组合卡底。生成原图、筛选说明和提示词应一起保留，便于修改同一风格；候选图不直接覆盖现有游戏资源。

## 9. 精修与验收

评审本轮精制卡纸样稿时同时检查三个用途，不能只依据收藏册空框大图判断完成。优先检查：

1. 去掉主图或转成灰度后，三个主类是否仍能快速分辨。
2. 收藏册大图的边缘和装饰是否清楚，中央是否足够容纳完整主图。
3. 缩到 64 和 32 像素后，边框是否变成噪声，凹口和尖顶是否消失。
4. 普通卡与载荷变体的主图位置是否一致，角标是否可读且未遮住主要特征。
5. 顶部居中的数量是否与装饰冲突，右下角标是否被画布裁切。
6. 地面牌堆是否一眼看成平躺叠放，厚度是否仍是纸，底部是否贴地。
7. 不同形状叠放时是否自然遮挡，是否保持纸层接触对齐；是否误用爆炸分层、悬空间距或扇开姿态强行展示卡牌类别。
8. 游戏纹理编译后是否出现透明边缘、压缩色边或过度模糊；源图好看不等于实机验收完成。
9. 原 A 左上、右下两处内侧卷角、翻折及其对应阴影是否已移除，局部纸面是否连续。
10. 与 A 结构对照，三种外轮廓、框宽、双线结构、角标位置与浅暖灰渐变是否保留；是否减少了明显裂纹、破口、污斑与密集排线，仍有手绘感与饱满层次。
11. 放入火焰、冰霜、重弹和武器或工具四种实际主图后，主图是否仍是视觉中心；暖色、冷色、深色和实体主体是否都清楚，边框高光是否过亮抢眼。
12. 魔力感是否来自明暗层次、亮核、晶面、清楚的轨迹或重复；是否错误地把所有卡统一处理成大泛光或满底魔法阵。
13. 对照 RRR 与 RHR，六角夹层缺角处是否出现上 R 悬边、下 R 承托纸面之间的退进阴影凹槽；是否被浅色矩形侧墙补满，或错误贯穿下方 R。
14. RRH 最底层缺角处是否露出悬边和地面暗影，RHH 的两张底牌是否都收窄；是否错误增加矩形底座。N 顶牌组合的前缘是否遵循相同规则。
15. 原版直用清单中的卡是否确实使用原版素材；主体是否完整位于边框内缘以内，并在安全间距及角标约束下尽量大；是否出现重绘、非等比拉伸、裁切可见部件或越框。对 `whirl`、`thrust`、`slash` 三个明确例外，检查单绘武器是否保持原版识别特征，旋转、前刺、挥砍轨迹是否清楚且完整位于框内。

后续实施顺序为：评审精制魔法卡纸边框样稿 → 放入火焰、冰霜、重弹和武器或工具四种主图检验 → 精修三主类高清母版与各用途资源 → 定稿机制符号 → 接入主类与标签数据及信息面板 → 替换正式资源并实机检查。逐卡分类映射与参数文案应单独核对，不能把本规范的例子当作完整卡表。
