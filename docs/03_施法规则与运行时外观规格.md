# 施法规则与运行时外观规格

状态：设计修订，尚未实现。本文明确采用普通法术回绕和运行时三段拼装，取代早期方案中的“不支持回绕”“修饰只绑定下一节点”“缺蓝等待整组”“全组合预生成”。本轮只调整文档。

实现所需数据契约、完整初始卡表、RPC 协议和任务顺序见 [开发执行规格](04_开发执行规格.md)。本文件确定规则；执行规格提供默认参数与落地步骤。

## 依据与适配边界

用户提供的[法杖](https://noita.wiki.gg/zh/wiki/法杖)和[基础机制指南](https://noita.wiki.gg/zh/wiki/基础攻略：法杖机制指南)作为入口，并补查[进阶指南](https://noita.wiki.gg/zh/wiki/进阶攻略：法杖机制指南)和[专家攻略 抽取](https://noita.wiki.gg/zh/wiki/专家攻略：抽取)。站点直读返回 403，搜索索引可返回相关段落；当前核对覆盖普通抽取、施法块、缺蓝与回绕，不代表已核对 Noita 原代码及所有特殊法术。

继承其核心抽牌模型；伤害数值、轨迹合成、控制效果、频率下限和预算保护属于本 Mod 的适配规则。指南能明确“哪些法术一起执行”，但不能自动决定本 Mod 自定义爆炸、吸血和 DST 碰撞的全部细节。

## 执行状态

每张卡有稳定实例 ID 与原始槽位。法杖维护待抽牌库、当前手牌、弃牌堆；施法块另存修饰状态和待生成的投射物。手牌不等于施法块，同次施法可因触发器产生多个块。装填时非乱序按原槽位排列，乱序用服务端随机状态洗牌；不能每抽一张都独立随机，也不能把已用卡立刻放回待抽池。

普通子弹不追加抽取，修饰追加一次，多重卡追加相应次数。卡片效果完成后继续外层尚未完成的抽取；基础多发与多重卡不简单相乘。例如基础双发抽到“双重施法、火花、魔法箭、能量球”，在费用足够且无其他修饰时，共生成三颗投射物。

施法块收集完毕后统一应用块内修饰，包括在投射物之后才执行的修饰。已在同一个块中的投射物不会因为卡片先后而丢失修饰。这遵循[进阶指南的施法块说明](https://noita.wiki.gg/zh/wiki/进阶攻略：法杖机制指南)。

触发器创建载体投射物与独立载荷块。首版约定载荷从默认投射物修饰状态开始，父块修饰不自动复制给载荷；载荷内修饰也不反向作用于载体。载荷建立时支付费用并冻结法术组成与静态参数；随机散射在实际释放时计算。载荷的施法延迟不增加父块施法延迟，回充修正仍记入本轮累计值。

## 紧凑模板与散射执行（2026-11-09 已实现）

本节记录当前实现，覆盖早期设计中与模板展开、散射缓存有关的约定。

- 编译器保留紧凑执行块。重复修饰保存为块的 `copies`，触发载荷保存为子块引用；预览和实际施法都不提前展开重复子树。
- 双重、三重施法继续在同一块中抽牌，共享该块修饰作用域；触发载荷创建独立作用域。重复复制不会重新抽牌或重复扣蓝。
- 执行器直接遍历当前块的重复次数，创建当前要释放的实体。相同参数共享只读描述，伤害衰减和副本效果限制按参数变体缓存；命中记录、寿命、触发状态和预算归各实体独立所有。
- 每次释放弹体时重新生成散射偏角，同一载体重复触发也会重新随机。固定阵型角不变，零散射不引入随机偏角。施法时分出独立随机流，后续触发不会回写已提交的牌库随机状态；相同初始状态与事件顺序可复现。此规则对齐 Noita 的发射散射行为，不追求其引擎随机序列逐值一致。
- 预算通过模板递归计数，仍在施法时预留首次载荷，命中重放按原规则申请额外预算。玩家已有的可选限制保持原义，不增加隐藏实体上限。
- 载荷蛋保存可达的紧凑模板、继承的伤害倍率/副本限制和独立随机种子，不保存运行中实体或逐弹散射缓存。旧存档中的展开载荷仍可执行，旧 `angles` 缓存不再控制新释放弹体的方向。

例如六次三倍重复后接触发火花、魔法箭，只保留两个块：根块以 `copies=729` 发射火花，所有火花引用同一个魔法箭载荷模板。根块在施法当下执行；箭在各载体触发时生成。模板复用不减少实际产生的实体数量，也不省去它们的碰撞或网络开销。

实现入口为 `nw/compiler.lua`、`nw/cast_templates.lua`、`nw/executor.lua`。回归覆盖见 `tests/test_template_reuse.lua`、`tests/test_persistent_fields.lua` 和 `tests/test_modifier_scope.lua`。

## 回绕与缺蓝

法术追加抽取遇到空牌库，可将弃牌堆回收并按当前法杖的装填规则排序后继续抽取；当前手牌留在手牌区。基础多发自身不足时不触发这一行为。普通回绕设置本次结束后回充标志，不等于立即开始下一轮，也不允许当前手牌被无条件重复利用。[抽取与回绕依据](https://noita.wiki.gg/zh/wiki/专家攻略：抽取)

费用不够的卡不执行、不扣费，直接弃置，不占有效抽取名额；随后继续找可执行卡。这与“整组缺蓝就一直等待”不同。此前成功执行的修饰已经消耗法力，即使后面没有可用子弹也不退费。超过最大法力的卡保留并警告，在法力条件不足时仍按跳过处理。负耗蓝类卡若后续引入，必须单独验证与回绕的交互；当前 24 卡首版不包含额外法力卡。

为避免全缺蓝或无输出组合造成无限检查，本 Mod 限定每次预载最多 128 次取牌尝试、最多一次普通回绕，并保留执行节点 32、触发深度 2 上限。没有可执行卡时结束为空施法并进入回充；达到安全上限则提示具体原因，禁止无界循环。这些是联机保护规则，不作为 Noita 全部高级机制的描述。

施法结束手牌移入弃牌堆；若牌库已空或发生回绕，则本轮结束，回收所有卡进入后续装填。卡在一轮中经回绕再次成功执行时，再扣一次费用并再计入相应回充修正。回充等待与最后一次根块施法等待同时起算，取较长者决定下次允许时间。

## 必须通过的规则用例

以下默认非乱序、基础单发、法力足够，费用示例为测试数据而非平衡数值。

| 卡序列或情境 | 预期结果 |
| --- | --- |
| 火花 → 双重 → 魔法箭 | 第一发火花；第二发魔法箭，并回收上次弃置的火花补足双重；随后回充 |
| 双重 → 火花，弃牌堆为空 | 发出一颗火花；不能把本次手中的火花拿回来补第二颗 |
| 火花 → 伤害强化 | 第一发普通火花；第二次修饰抽取触发回绕，发出强化火花 |
| 双重 → 魔法箭 → 强化 → 魔法箭 | 两箭同块，均被强化 |
| 基础双发，只有火花一张 | 发出一颗后回充；基础多发本身不会凭空复制卡 |
| 双重 → 高耗弹 → 火花 → 魔法箭，高耗弹费用超过当前法力 | 跳过高耗弹，继续抽到能支付的火花与魔法箭 |
| 强化费 10、重弹费 50、火花费 5，当前蓝 20，排列为强化 → 重弹 → 火花 | 强化后剩 10；跳过重弹；执行火花后剩 5，产生强化火花 |
| 强化 → 命中触发弹 → 火花 | 强化载体；载荷火花独立，未获得父块强化 |
| 命中触发弹 → 强化 → 火花 | 普通载体；命中产生强化火花 |
| 全部法术当前不可支付 | 有界结束并等待回充，不在单次请求中死循环 |
| 乱序得到与上例完全相同的排列 | 执行结果相同；乱序仅改变排列，不改变抽牌规则 |

编辑器不以静态前缀结构不完整阻止保存。显示满蓝模拟及警告；若缺蓝、乱序会改变结果，要显示条件，不能给出恒定输出承诺。回绕的演示应显示三类牌区移动，而非仅高亮槽位游标。

## 本 Mod 的法术交互约定

以下是 DST 适配决策，不声称是 Noita 对应法术的精确实现。

| 交互 | 规则 |
| --- | --- |
| 多个伤害／速度修饰 | 伤害增量相加；速度倍率相乘、初速增量相加，初速及运行速度上限统一为 95（2026-11-15 试调）；重复布尔能力不重复挂载监听 |
| 追踪加曲线 | 追踪改变中心前进方向，正弦和螺旋作为局部偏移叠加，最终路径用于服务器扫掠；振幅与速度有上限 |
| 穿透加命中触发 | 首次合法目标命中触发载荷一次，载体可按穿透余额继续飞行 |
| 弹跳加爆炸 | 障碍碰撞且有弹跳次数时先反射；没有次数时终止并爆炸；不因每次反射重复爆炸 |
| 穿透加爆炸 | 首次合法目标命中或最终终止时爆炸一次，之后穿透不会重复产生该爆炸 |
| 连锁电弧 | 从首次合法目标命中发起一次；连锁伤害不能再发起连锁、触发载荷或爆炸 |
| 吸血 | 统计直接弹伤与爆炸的实际有效伤害，统一按施法者每秒封顶；连锁与持续灼烧不计，避免递归收益 |
| 同时出现触发、爆炸、连锁 | 合法碰撞 → 直接伤害 → 一次性载荷／爆炸／连锁事件 → 决定穿透或终止；事件均使用独立“已执行”标记 |

友方过滤在选取目标和实际结算时都执行。穿透命中列表防止同弹重复伤害同一目标；爆炸另按事件结算。命中触发器不因超时或预算清理被伪装成命中；定时器载体提前销毁则不再到时触发。

2026-11-15 速度上限试调：`nw/spell_limits.lua` 的 `max_speed=95` 统一控制投射物／触发弹初速、移动场地初速、场地产生的子弹初速，以及 `flight.lua` 的环绕推进和最终水平运动限速。后续全面核查补齐直接初始化、反弹、场地读档／外部冲量、盾牌环绕、原版海鱼抛出及武器交接入口，运动更新按实际世界水平速度统一限至 95。巨化／缩小的移动场地写入马达时补偿实体缩放，避免尺寸暗中放大移速；返航飞刃、辉煌弹和龙卷风的原版交接限制仅挂在本 Mod 生成的实例上。投射物与派生弹的速度下限仍为 2，静态场地仍可为 0；环绕半径、角速度、追踪加速度和暗雾的传送识别阈值沿用原规则。旧存档描述符不重新编译，恢复运动时对速度向量保持方向地限幅；抛物竖直速度和原版视觉缩放补偿独立计算。

## 服务端事务与预算

预载在牌区、法力、随机状态的副本上执行，不生成真实实体。正常缺蓝跳过属于成功执行路径；预载结果通过预算后一次提交状态。正常空施法提交已发生的合法扣费与牌区变化。

若超过编译安全上限或资源预算，丢弃本次临时结果、保留原法力与牌区，并施加短失败冷却与明确反馈；不同于缺蓝跳过。预留载体及最大载荷的弹体预算，载荷产生时转换预留额度；载体提前销毁、施法者离线或转分片后释放预留并取消待触发载荷。此取消规则是联机适配。弹体预算的计数必须包含预留额度，不能只数已存在实体。

## 运行时外观结构

一个物品保存三段部件 ID、长度档与装饰档。资源中保存独立部件的图片及帧，不保存全组合图片。

地面表现使用一个包含 head/body/tail/detail symbol 的动画模板，分别替换 symbol；装备后在拥有者上挂接一个表现实体，跟随 swap_object，实体内部继续分别替换三段。专服不创建纯客户端美术实体。客户端表现对象不保存玩法数据，不独立决定属性。

需要独立节奏的水晶闪烁可采用有限额外局部表现层；三段仍共享一套连接坐标，不各自按世界坐标追着角色跑。局部 symbol 帧必须与素材的动画帧数量匹配；单纯替换图片并不会自动产生新的动画时间线。

短、中、长杖身各提供对应素材与动画布局，例如 ground_short、ground_medium、ground_long 和 held_short、held_medium、held_long。布局固定握持原点，改变杖头、杖尾的连接位置；可把杖身进一步拆成握柄、延长段和装饰段，有限数量启用或替换。不能只换一张长杖身图片而不移动杖头，也不直接拉伸整根法杖。

库存、容器、拖拽与检查预览使用同一描述的分层图片控件。需要验证各入口的刷新时机、缩放、堆叠数字与背景遮挡，不能假定物品的动画替换会自动影响库存图标。

本地原版参考位于 scripts.zip 内：balloon_held_child.lua 第 56—76 行展示客户端表现对象跟随手部，staff_lunarplant.lua 第 12—29 行展示手持／地面跟随切换，king_cane.lua 第 397—412 行展示按网络字段替换宝石。实现可参考这些模式，具体接口参数需在编码前继续核对。

## P0 必须验证的资源路径

使用已经发现的本机 Don’t Starve Mod Tools，先验证 PNG／SCML 等源资源到游戏动画及图集的编译流程，保留可编辑源文件。检查至少两个杖头、三个长度、两个杖尾可以运行时交叉组合，且无需生成每个组合的完整资源。

验证地面、手持、库存、拖拽、预览五处一致；站立、奔跑、施法、镜像转向、骑乘、丢弃与重新装备时接缝与遮挡正确。验证晚加入、实体重新进入视野、跨洞穴和重启不换样。检查主机与远端客户端效果一致，卸下或实体移除后表现实体清零。任一关键入口未通过，记录具体失败，不以通用占位图宣称外观需求完成。

此路径不需要为每个外观新增 prefab，不需要预合成所有组合，也不要求安装图像服务插件；官方编译工具能否在当前环境完整运行仍待 P0 测试。
