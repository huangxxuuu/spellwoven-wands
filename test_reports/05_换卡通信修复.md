# 换卡通信修复：0.3.1-prototype

日期：2026-10-29。用户报告已贴近奥术台，却无法通过面板更换卡片。

## 原因与测试遗漏

0.3.0 的面板发送 `card.GUID`、`wand.GUID` 两个普通数字。服务器把它们与自己的 `wand.GUID`、`Ents[guid]` 比对。本地 GUID 不保证在两个进程间一致，数字 RPC 参数不会自动变成对应服务器实体；法杖编号不匹配时处理函数直接返回，连距离检查都没有执行，也没有回执。

截图中“需靠近奥术台”是固定文案，不是距离检查返回的结果。之前的自动测试直接调用服务器换卡事务，绕过了 UI 请求参数和 RPC 处理入口，所以不能证明真实客户端可以换卡。

## 修正

- 使用 `Network:GetNetworkID()` 传输法杖与卡片身份。服务器只在当前装备和请求者主物品栏中匹配网络 ID，继续校验归属、槽位、距离和配置版本。
- RPC 处理抽到 `nw/edit_protocol.lua`；客户端请求与回执放在 `nw/editor_client.lua`。
- 每次换卡携带请求序号；返回成功或明确失败原因，界面显示提交中、成功、失败、超时。过时请求的回执不能覆盖后来请求的提示。
- 编辑心跳由服务器回报当前杖的奥术台距离状态。界面区分“正在确认”“已靠近”“未检测到”，不再使用固定距离说明冒充状态。
- 原存档、法杖、奥术台和法术卡均可沿用，无需重新生成。距离阈值保持 4 个世界单位。

## 验证与边界

新增 `test_edit_protocol.lua`：刻意让客户端／服务器 GUID 不同，但网络 ID 相同，从客户端提交函数经过服务端处理到客户端回执，验证实际替换与取出；同时覆盖错误 GUID、卡片移走、旧配置版本、距离不足、未装备、重复发送抑制、超时和旧回执。

全部 11 组 Lua 测试通过，29 个 Mod Lua 文件语法通过。真实专服自检改为从 `GetModRPCHandler("nw_weave","edit")` 入口，使用引擎生成的网络 ID 完成满包替换，并继续检查槽位和卡片的实际保存记录恢复。

以上没有启动真实图形客户端发送换卡 RPC，也没有新增第二玩家验证。因此仍需重启游戏复测点击换卡及结果文字，不将模拟的跨进程身份测试称为真实双端联机通过。
